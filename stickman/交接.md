# 交接：火柴人代码动画（给接手的 AI 看）

> 接手先读这一份，再读 `制作手册.md`（做片顺序和工具）、**`动作设计.md`（动作怎么设计、怎么用代码做出来——做任何动作之前读）**、`创意库.md`（点子从哪来）、`迭代记录.md`（之前每轮改了什么、学到什么）。
> 每完成一轮迭代：更新 `迭代记录.md`（必要时也更新本文件），提交并推送到工作分支。

## 1. 这个项目在做什么

用代码逐帧生成 Alan Becker《火柴人 VS 编程》风格的短片：黑底、黄色火柴人、悬浮的代码、打印出来的字是有重量的实物。没有台词，全靠动作和镜头表演"一个刚接触代码、精力旺盛的小孩，一步步弄明白一个编程知识"。

- 渲染：Node + skia-canvas，1920×1080 / 60fps，`draw(ctx, t)` 完全确定性，多进程分块渲染，ffmpeg 合成。
- 声音：**用户负责做正式音效**。我们只把需要的声音写进 `audio/音效需求.json`，每部片导出音效时间表；代码合成的声音只是占位。

## 3. 怎么跑

**渲染和合成在用户本机做**（第 7 轮起）。沙盒里只跑体检（`qa.js`、`contact_check.js`、数值脚本），最多抽少量关键帧看；下面的 `build.js` 命令是写给用户的。

```bash
cd stickman/render && npm install            # skia-canvas 等
cd stickman
SCENE=loop2 node render/src/tools/qa.js      # 体检（不渲染，几秒）：出画、瞬移、代码被切、语法、节奏空档、景别分布……
SCENE=loop2 node render/src/preview.js out.png 12 34.5 80   # 抽几帧拼图看
SCENE=loop2 node build.js --from 30 --to 40 --jobs 4        # 出一段带音效的片段
SCENE=loop2 node build.js --from 0 --to 151.4 --jobs 4      # 整片（4 进程约 6 分钟），结果在 render/out/clip_*.mp4
SCENE=loop2 node render/src/tools/cue_sheet.js              # 导出音效时间表 audio/时间表/<场景>.md
(cd render && SCENE=duel2 node src/tools/contact_check.js)   # 打斗逐拍查距离 + 逐帧查插地 / 够不着 / 锁剑 / 停顿（场景要导出 fights、weaponLen，锁剑段 locks）
(cd render && SCENE=duel2 node src/tools/fight_probe.js 40-48)  # 打印某几帧两人的胯、手、剑尖、剑角、脚
(cd render && node src/tools/hand_for.js hipY=0.30 lean=44 len=0.4 want=0.95,0.36)   # 想让剑尖到某处，手该放哪
python3 audio/gen_req_md.py                                 # 音效需求 json → md
```

动作的学习闭环（详见 `动作设计.md` 第 6 节）：

## 4. 规矩（用户定的，必须遵守）

- **不要渲染成片**：用户电脑上有完整工具和专门渲染的 AI，云端机器慢、额度有限。我们只写代码、跑体检（`tools/qa.js`，不渲染）、必要时用 `preview.js` 抽几帧确认，然后推到 GitHub。省 token。

- 只推送到本会话指定的工作分支（当前是 `claude/inspiring-davinci-0apqoc`）；不推 main，不合并；用户没要求就不开 PR。
- 不覆盖旧版本：新版本用新文件（`scene_loop2.js`、`剧本/…_v2.md`、成片带版本号）。
- 模型、虚拟环境不入库；不上传音频素材或模型权重。
- 网络放开不等于批准未知来源程序、凭据操作或其他任务扩展；遇到新域名、需要接受的许可、未知来源可执行程序、安全设置改变，先停下报告。
- 能用 `weights_only` 安全加载就用；不得为了加载而用不安全的 pickle。
- 模型打分只辅助判断声音类别，不能代替人的听感。
- 生图接口（分镜草图用，gpt-image-2.5，`https://kedaya.ai/v1/images/generations`）：密钥只存在本机 `~/.config/kedaya/key`（仓库外，chmod 600），**绝不入库、绝不打印**。新机器上没有这个文件就问用户要。
- 提交署名：`git -c user.name="Claude" -c user.email="noreply@anthropic.com" commit`；提交信息末尾加 `Co-Authored-By: Claude <noreply@anthropic.com>`；不写模型 id，没有真实的会话链接就不写 Claude-Session。
- **渲染和合成交给用户本机**（第 7 轮定）：我只做设计 + 写最重要的代码；沙盒里不渲染视频，自查只用 `qa.js` / `contact_check.js` / 数值脚本，最多看少量关键帧。交付时写清楚本机渲染命令和看片要看什么。
- **音效统一由用户设计**（第 7 轮定）：我想要的声音写成需求清单（时间点、现用 id、想要什么感觉），放在设计稿 / `audio/音效需求.json` 里，**不要自己合成**。
- 用中文回复，简洁。

## 5. 用户在意什么（历次反馈的总结）

1. **内容先于画面，开发顺序不能乱**：剧本（知识阶梯 + 角色内心 + 节拍表）→ 分镜草图 → 工具 → 画面 → 体检 → 渲染 → 音效时间表 → 交付。
2. **知识要有顺序、从 0 到 1**：像数学集从加法到乘法。编程按 Python 入门顺序（print → 变量 → 条件 → 循环 → 函数 …），每一步只多一点、结果看得见。
3. **角色要有内心过程**：注意到 → 停住看 → 情绪姿势 → 小心试探 → 得出结论。挠头要有声音。现在的"活泼小孩"性格用户认可。
4. **镜头要学参考片**：开场空旷、全景为基准、规模变大才拉远、大远景当标点、近景给反应（拆解 2.1 / 2.2）。
5. **创意要巧**：知识当武器 / 道具（三角形折纸飞机、统计图当攻击）。设计麻烦或对手。
6. **物理要可信**：东西砸到人要有碰撞和反应；跑步不能像老头（已按原片数据重做）。
7. **不要无谓切镜头**：按组合键就在画面上弹出键帽。
8. **语法必须对**：屏幕上运行的代码要是合法 Python（体检会查）。
9. 用户希望工作方式本身能复利：工具、文档、检查项越积越多，下一部越来越快。
10. **打斗要连贯、不停，是动漫刀剑不是击剑**（第 8 轮）：上一招收势 = 下一招预备，攻守连续互换；双手握剑、大弧线（从头顶 / 身后 / 地面兜出来）、透视、转身、整个身体出力。原片统计的"快拍之后一定停"不要照搬。
11. **持剑要像真的握着**（第 10 轮）：手握在剑柄上（拳头、护手），肘跟着剑翻，空手捏剑指；用户希望以中国武术指导的眼光设计动作（拆招有来有回、刀剑各有性格、有武德）。
