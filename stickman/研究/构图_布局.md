# 构图和布局：角色、代码、输出、道具在画面里怎么摆

研究问题：参考片里，人、代码、输出的字、道具在画面里放在哪、多大、同时放几样。
我们自己片子的毛病：代码占掉半个画面、远景里人太小、东西堆得乱。

素材：编程集 v3（30fps，主力）、数学集 v2、几何集 v1。画面 1920×1080。
**H = 主角站直时的身高**（不是画面高）。"画高 / 画宽" = 占整个画面高 / 宽的比例。
坐标：x 从左 0 到右 1，y 从上 0 到下 1。三分线 = 0.33 / 0.67。
右上角的 bilibili 水印不算。

## 2. 代码块：放哪、多大、什么时候来去

### 2.1 主角自己写的代码（第一幕 0:25–2:24 最典型）

- **位置：在主角"看的那一侧"的上方。** 87% 的帧代码在主角左边，主角面朝左。
  - 块的底边 ≈ 主角头顶的高度（头顶减块底，中位 0.07H；10%–90% 范围 −0.02H 到 0.77H）。
  - 块中心离主角中心，水平约 1.1H（中位 1.07H）。
  - 块的右边缘 ≈ 主角的左边缘（中位只差 0.035 画宽）。代码块像一块"挂在人左上方的黑板"，右下角正好碰到人。
  - **代码几乎不压人**：只有 7% 的帧代码框和人框重叠。
  - 只有一个短词时（`hello` 0:17.4、`print(_` 0:25），直接放在头顶正上方，离头 0.05–0.4H。
- **在画面里的大小**（第一幕，全片扫描 458 帧）：
  - 宽：中位 33% 画宽，90% 的帧不超过 43%。
  - 高：中位 24% 画高，90% 不超过 33%。
  - 面积：中位 **8%** 画面，90% 不超过 **12%**。
  - 位置：中心 x 中位 0.46，顶边中位 y 0.18，底边中位 y 0.43。代码占的是画面上面 1/5 到 2/5 这一条。
- **字的大小（按主角身高算，镜头远近都一样）**：
  - 行距 ≈ **0.3H**（0:48.4 0.34H、1:13.3 0.31H、0:56 0.26H、2:22.5 0.32H）。
  - 数字 / 大写字高 ≈ **0.15H** ≈ 0.7 个头的直径（1:13.3：6.7% 画高 / 人 43%）。
  - 括号从顶到底 ≈ 0.22H。
  - 也就是说：**代码字号是世界里固定的大小，跟着镜头一起缩放**。要放更多行，是镜头拉远，不是字变小（2:22.5 五行时行距在画面里变成 6.8%，但相对人还是 0.32H）。
- **行数上限**：
  - 全景（人 35–50% 画高）里最多 **3 行**：0:25–1:57 整整一分半钟都是 1–3 行，满了就选中删掉重写（1:34.5）。
  - 4–6 行：镜头拉到人约 20% 画高（2:22.5、2:52、6:06.5），画面里行距 7–9%。
  - 更多行时分主次：`def` 那一行和调用那一行正常大，函数体缩到一半（6:23 `nuke`：4.7% 对 2.3%；4:30 `fire`：5.3% 对 1.3–2%）。
  - 一整面代码墙（5:22、5:59.7，10 行以上）只当背景用，人缩到 4–10%。
  - **能读的代码行，画面里的行距从不小于约 6% 画高**；更小的是"纹理"，不打算让人读。
- **宽度**：中位 0.33 画宽 ≈ 1.4H。最长的一行可以到 0.7 画宽（6:06.5），但这时人已缩到 20% 以下。

### 2.2 对手（电脑）写的代码

- **挂在电脑上方**，不挂在主角身上：块底离电脑 0.1–0.2 画高，块的左边大致和电脑左边对齐（2:33.5、3:02.5、3:17、4:30 的 `fire(5)`）。
- 字号也是世界比例：行距 ≈ 电脑的宽度（第一幕电脑宽约 0.12 画宽、行距 13%；2:33.5 电脑宽 0.08 画宽、行距 7.1%）。
- 揭示镜头（2:29–2:33）：大远景，电脑在一头（x 0.12），主角在另一头（x 0.83，7% 画高），中间全空。观众一眼就看出"两边"。
- 对手写代码时常常主角不在画面（3:02.5、3:17），镜头只给"电脑 + 它头上的代码"。

### 2.3 什么时候出现、什么时候离开

- **第一幕：代码是常驻的黑板。** 0:25–1:52 代码一直在画面里（全片扫描：第一幕 76% 的时间有代码）。换内容靠"选中 → 删除 → 重写"，不是淡出。
- **第二幕（动作段）：代码只露一下。** 有代码的时间只剩 36%；每段中位 **2 秒**（25%–75%：0.9–3.5 秒），两段之间中位隔 3 秒。
- **离开的方式：镜头走了，代码留在原地。** 代码是世界里的东西，不跟镜头走。运行后 0.3–0.5 秒，镜头去跟结果或主角，代码从画面边上滑出去（2:42、3:14）。或者镜头拉远，代码缩成小字（2:58.8）。没有见到"代码淡出"。
- **出现的方式**：一个字一个字打出来，光标在最后；对手的代码同样在电脑上方逐字出现。
- 复制出来的行一边往下飘一边变淡（3:12.5–3:13.8），这是唯一的"淡出"。
- 第三幕几乎没有代码（7%），只有 `hello?` 一个词和训练段的满屏代码。

## 4. 一个画面里放几样东西

- **常态 3–4 组**：人 + 电脑 + 代码 + 输出（0:48.4、0:56、1:13.3、2:16）。
- **最多 4 组看得清。** 到第 5 组时一定有一样"降级"：
  - 代码缩成小字或分主次（4:30、4:35.5）；
  - 或者干脆没有代码（3:55 柱状图、3:23.5 追逐、5:05 方块）；
  - 或者主角缩成小点，代码当背景（5:22）。
- **画面满了怎么办（按出现多少排）**：
  1. 镜头跟着动作走，代码自然出画（最多）。
  2. 拉远，让代码和人都变小（2:22.5、5:22）。
  3. 切到代码特写，人不在画面，只看改的那一个字（6:02.5、3:17）。
  4. 删代码（第一幕选中删除）。
- **开场和大事件前，画面只有 1–2 样**：0:00 只有光标；0:09 只有人 + 电脑；2:30 揭示时人和电脑在画面两头，中间全空。
- 输出越来越多时（BARK 洪水），输出堆在地面一条带里（y 0.65–0.80），不往上堆到代码区。

## 7. 可以直接写成代码的构图规则

H = 主角站立身高；"画高 / 画宽" 是画面的比例。

1. **代码在世界里，不在屏幕上。** 代码跟镜头一起缩放、平移。行距 = 0.3H，字高（大写 / 数字）= 0.15H。（0:48.4、1:13.3、2:22.5 三处都是 0.31–0.34H）
2. **主角自己的代码块放在他看的那一侧的上方**：块底 = 头顶 + 0～0.1H；块的近边 = 主角身体外缘（水平间距 ≈ 0）；块中心离人中心 ≈ 1.1H。代码框不能和人框重叠。只有一个短词时放在头顶正上方 0.05–0.3H。（第一幕 327 帧统计；0:17.4、0:48.4、1:13.3）
3. **代码块在画面里的面积 ≤ 12%，宽 ≤ 0.45 画宽，高 ≤ 0.33 画高。** 中位是 8% / 0.33 / 0.24。超过就拉镜头，不是缩字。（第一幕 p90）
4. **全景里最多 3 行代码。** 4–6 行时镜头拉远到人 ≈ 20% 画高；能读的行在画面里的行距 ≥ 6% 画高；多于 6 行时只让首行和调用行正常大，其它行缩到一半当纹理。（0:25–1:57；2:22.5；6:23）
5. **打字段用对角线**：代码中心 x ≈ 0.45、y ≈ 0.3；主角中心 x 在 0.6–0.8（三分线附近），头顶 y ≈ 0.5，脚 y ≈ 0.85–0.93；上面 40% 留给代码。（第一幕中位：代码 x 0.46、人 x 0.61、人顶 0.51、脚 0.81）
6. **输出是小石子**：普通输出字高 0.05–0.1H，落在人面前 1H 的地上、代码块下方；地上的输出堆只占 y 0.65–0.80 这一条，不往上堆。要当道具用的才放大到 0.3–0.7H。（0:34.6、0:56、1:13.3、2:16、2:27.6、4:22）
7. **对手代码挂在电脑上**：块底在电脑上方 0.1–0.2 画高，左边和电脑对齐，行距 = 电脑宽度。（2:33.5、3:02.5、3:17）
8. **动作段代码只露 1–4 秒**，运行后 0.3–0.5 秒镜头离开，代码留在原地出画；不要做淡出。打字教学段代码常驻，靠"选中 → 删除"换内容。（第二幕片段中位 2 秒；2:42、3:14）
9. **一屏最多 4 组东西**（人、电脑、代码、输出 / 对手 / 大道具）。第 5 组出现时，必须让一样降级：去掉代码、代码缩成小字、或者拉远让人变小。（3:55、4:30、4:35.5、5:22）
10. **打斗两人中点在画面中间（0.45–0.55），间距 1.3–2.8H，脚踩在 y ≈ 0.68（下三分线），人高 20–25% 画高**；地面渐变从脚下开始往下变亮。（v2 4:10、4:41.5、7:26、7:27.5）
11. **近景（人 >45% 画高）把人放在 x ≈ 0.12–0.33 或 0.67–0.88**，看的方向留 2/3 画面给对手、电脑或代码。（v3 8:22、1:20；v2 1:44）
12. **开场和揭示时画面只放 1–2 样东西**，揭示对立时两方放画面两头（x ≈ 0.1 和 0.85），中间空着。（v3 0:00–0:12、2:30）

## 8. 对照我们的毛病

| 我们的毛病 | 原片的数字 |
|---|---|
| 代码占掉半个画面 | 原片代码中位只占 8% 画面，最多约 12%；宽约 1/3 画宽；只在上面 1/5–2/5 那一条 |
| 人在远景里太小 | 有代码的段落人 35–50% 画高；动作段 10–25%；小于 10% 只用来揭示和大场面，每次几秒 |
| 东西堆得乱 | 一屏最多 4 组；代码左上、人右下、输出在地上，三者不重叠；满了就拉镜头或让镜头带走代码 |
