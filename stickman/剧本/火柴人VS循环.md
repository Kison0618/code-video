# 火柴人 VS 循环（剧本 v1）

> 先定内容，再做画面。本文件是唯一的依据：画面、镜头、声音都按这里的节拍做；改内容先改这里。

## 一句话

一个火柴人在黑暗里醒来，从一个光标开始，一步步摸索出 `print`、然后被"重复"折磨、发现 `for` 循环、玩上瘾把循环开到 100、最后误写出 `while True` 被自己造出的无穷无尽的 `hi` 淹没，用 `Ctrl+C` 救了自己。

## 讲什么知识（从 0 到 1，每一步只多知道一点）

| 步 | 主角学到的 | 怎么学到的（看得见的结果） |
|---|---|---|
| 1 | 光标是"可以碰的东西"，但碰它没用 | 戳光标，光标只是抖一下 |
| 2 | 按键 = 光标那里出字 | 按一个键，冒出一个字母 |
| 3 | 随便写的词会报错 | `hello` → 变红 + NameError |
| 4 | `print("hi")` 会把 hi 变成真东西 | hi 掉在地上，戳得动 |
| 5 | 想要很多个，就得一行一行写，很累 | 手敲三行，越敲越慢，甩手 |
| 6 | `for` 能替你重复，但要缩进 | 第一次没缩进 → IndentationError；按 Tab 缩进后 3 个 hi 一起掉下来 |
| 7 | 括号里的数字决定重复几次 | 3 → 10 → 100，hi 越来越多，100 个下成一场雨，把自己埋了 |
| 8 | `i` 每一次都不一样 | `print(i)`：0 1 2 … 9 排着队掉下来 |
| 9 | `while True` 永远不会停 | 一直停不下来，hi 淹没整个世界 |
| 10 | `Ctrl+C` 能强行停止 | KeyboardInterrupt，一切停住、消散 |

原则：每一步都是"试一下 → 看结果 → 反应 → 下一步"；结果必须是看得见的实物；观众和主角同时弄明白。

## 角色

- 黄色实心头的火柴人（编程集同款造型），没有台词、没有脸，全靠姿势和节奏表演。
- 性格：好奇、谨慎、容易得意，一得意就玩过头。
- 内心过程按 拆解 3.1 节：注意到 → 停住看 → 情绪姿势 → 小心试探 → 得出结论 → 下一步。

## 结构与节拍（总长约 2 分钟）

时间是目标值，做的时候允许 ±10%。镜头写法：远 = 远景（人占画面 < 25%），全 = 全景（整个人），中 = 中景（半身），近 = 近景（头肩），特 = 特写。

## 视觉规则

- 黑底，白字代码（VS Code Dark+ 配色），黄色主角，不超过 3 种颜色（报错的红例外）。
- 代码悬在半空、主角够得着的高度；输出的东西是实物，有重量、会弹、会堆起来。
- 镜头按 拆解 2.1 节：看反应推近、看规模拉远；在节拍上推拉，节拍之间稳住。
- 特效只在节拍上：报错推镜冲击、hi 雨的规模感、Ctrl+C 那一下画面定住和消散。

## 声音

- 需要的声音按 id 写在 `audio/音效需求.json`；每个场景导出音效时间表 `audio/时间表/<场景>.md`。
- 新增：`word_rain`（很多小字落地的连续雨声，按密度变化）、`dissolve`（所有字碎成灰的一声）、`tab`（Tab 键）、`interrupt`（Ctrl+C 的组合键）。
- 配乐：第一幕、第二幕前半安静（只有音效）；hi 雨开始进入轻快的配乐；第三幕逃命时最强；Ctrl+C 那一下切断，之后只剩音效。
