## 0. 设计原则（全部来自用户意见和原片实测）

**剧情**
1. 上一集已经探索过，这一集开头只"玩"几秒，**16 秒内出事**。
2. 复杂知识不在开头讲，**直接在打斗里用**；每个知识只给一个好看的效果。
3. **少造东西**；新出现的东西后面一定要用到，优先用上一集留下的（小蛇、`while`、`for` 砌墙、`Ctrl+C`）。
4. 对手**先悄悄出手**（观众看见、主角没看见），规则立住以后，打斗里才有悬念。

**动作**
5. 反应 0.1 秒到位、定 0.3 秒就接下一件事；惊讶不单独占镜头；不是每个发现都配一个动作。
6. 手只抓够得着的东西。
7. **打斗要连贯，中间不停**（用户看 duel1 的意见）：上一招的收势就是下一招的预备，"停"换成还在动的段落（较劲、滑退、翻滚）。停顿只放在回合和回合之间、放在剧情点上。
8. 打中不停帧、不震屏：1 帧光 + 火花 + 字形。

**主角和电脑**
9. 打斗里主角拿着电脑的时间 ≤25%；每 5–10 秒换一次人和电脑的关系（出事 → 电脑脱手 → 捡回来换一种姿势打字）。
10. 一次打字 ≤2.5 秒，只改一处就运行；改完接 1–7 秒身体动作。站着用一只前臂托电脑、单手打，空出的手做表演。
11. 主角**可以用手直接抓代码里的字**（借数学集、几何集）。

**构图**
12. 代码行距 0.3H、字高 0.15H，跟世界一起缩放；全景最多 3 行；放在主角看的那一侧上方，不压人；动作段代码只露 1–4 秒，然后镜头带走。
13. 一屏最多 4 组东西（人、电脑、代码、输出 / 对手 / 小蛇算一组）。
14. 揭示对立时两方放画面两头，中间空着。

## 1. 一句话

上一集他用 `Ctrl+C` 打断了无穷长的 hi 长蛇——被打断的输出没有消失，碎成了**乱码**，一直跟着他。它能把碰到的字变成乱码、吃进去，越吃越大，还偷偷改他的代码。他不会打架，只能边躲边写；被逼到绝境时**想起上一集的招**。最后他用 `try / except` 把每一次报错接住、反弹回去，乱码一层层吐出吃掉的字；手指停在删除键上时，**回忆揭开它的来历**——它是自己留下的东西。他没有删，加了一个 `#` 把它注释掉。最后一小团乱码变回一个 `hi`，接到小蛇尾巴上。

## 2. 角色设计卡

### 2.1 主角（黄色火柴人）

- 性格："精力旺盛的小孩"：好奇、得意忘形、怕但不认输。没有脸，靠身体演。
- **不会打架**：第二幕前半段靠躲、靠运气；越往后越会把代码和身体连起来用。
- **打字姿势按剧情一路往下走**（原片：站 → 跪 → 坐 → 趴 → 躺）：

| 段落 | 姿势 | 电脑在哪 |
|---|---|---|
| 冷开场、第一幕 | 站，一只前臂托电脑，单手打 | 手里 |
| 回合 1 | 电脑被撞飞 → 小蛇推回来 → **趴着**打 | 地上 |
| 回合 2 | 空手和乱码人对打；回忆后**扑过去跪着**快打 | 地上 → 脚边 |
| 回合 3 | 条件反射写好后**侧躺手撑头** | 地上 |
| 回合 4 | 站着**双手捧**（认真了）→ 被巨人一脚踢飞 | 手里 → 远处 |
| 第三幕 | 低谷**坐**着 → 站起来托着 → 结尾单手托、空手摸小蛇 | 手里 |

- 全片主角拿着电脑的时间约 35%，打斗段约 20%。

### 2.2 小蛇（三节 `hi hi hi`，上一集驯服的）

- 身体就是 `while n < 3: print("hi")` 的输出：**改数字就改长度**。这是它所有用法的来源。
- 用法（每样都在后面用到）：

| 时机 | 用法 |
|---|---|
| 开场 | 3 改 5，长两节（第一次悄悄出手发生在新长的一节上） |
| 第一幕 | 被乱码吃掉两节；主角把它拽回来 |
| 回合 1 | 把被撞飞的电脑推回到主角手边；`n < 10` 变成鞭子抽乱码；被缠住 → 改回 3 自救 |
| 回合 2 | 躲在墙后 |
| 第三幕 | 主角躺着不动时，它把被踢飞的电脑一点点推回来（低谷的转折） |
| 结尾 | 乱码最后一小团变回 `hi`，接到它尾巴上：四节 |

- 表演：会抬头、会缩、会蹭人；高兴时扭得快、害怕时缩成一团（三节叠在一起，这是故意的"挤"，和技术上的挤不同）。

### 2.3 乱码（对手）

**它是什么**：上一集被 `Ctrl+C` 打断的长蛇残骸。被打断、只写了一半的输出就是乱码。
**能力只有一个，全片不变**：碰到的字会变成乱码，然后被它吸走；吸了多少，它就长多大。主角的代码、小蛇、输出、砌的墙，全都是字。

**样子（解决"像一堆噪点"）**
- 字：`锟 斤 拷 烫 屯 Ã ¤ ÿ ¿ ½ ▯` 等，灰白色。
- **核心**：中间一个最大、最亮的 `�`（约 2.5 倍字号）。它的"眼睛"和"心脏"都是这个字。
- **轮廓**：外圈的字排得密，顺着轮廓的方向排（像鳞片），里面稀。待机时是一个半圆的小土堆。
- **整齐和乱是两种状态**：平时外圈的字方向一致、整团慢慢绕核心转（约 10 秒一圈）；只有吃东西、被打、发怒时才乱转、往外飞。
- **痕迹**：被它碰过、没被吃掉的字变成**暗灰色**乱码留在原地（地上一串脚印、墙上一片灰）。本体亮、痕迹暗、主角黄，三者不混。

**四个形态**

| 形态 | 大小 | 什么时候 | 样子 |
|---|---|---|---|
| 伪装 | 一行字 | 冷开场到第一幕 | 地上一行看起来正常的字（像上一集留下的输出），只有一个字微微抖 |
| 团 | 0.6H → 1H | 第一幕、回合 1 | 半圆土堆 + 核心 `�` |
| 人形 | 0.9H → 1.3H | 回合 2–4 | 骨头是一串串乱码字，头是 `�`；能用招式库（和主角一样的身体，所以能"学他"） |
| 巨人 | 3H+ | 回合 4 末尾、第三幕 | 人形放大，身体里能看见吃进去的整段代码在转 |

**固定的"表演词汇"**（每次都一样，让观众学会读它）

| 词汇 | 做法 | 依据 |
|---|---|---|
| 预备（大攻击前） | 缩到 0.7 倍（8 帧）→ 1 帧弹到 1.2 倍 → 边缘抖 9 帧 → 出手。**全片至少用 4 次** | 几何 4:16、6:32、7:36 |
| 盯住 | 外圈所有字 2 帧内转成同一个方向、尖朝主角，整团完全静止 10 帧，连转动也停 | 几何 4:28、7:37 |
| 出手前静止 | 小攻击前停 4 帧，大攻击前停约 1 秒 | 编程 3:37.7 |
| 吸字 + 打嗝 | 字被拉长吸进去（8 帧）→ 整团鼓 1.1 倍（3 帧）→ 核心闪一下被吃的那个字的原样（2 帧）→ 恢复 | 几何"吃"不变 |
| 爬 | 前沿伸出去抓住地面、后面收拢（尺蠖），接触点闪一下；慢、匀速，不跟主角的节奏 | 几何 4:29–4:50 |
| 被打 | 被打那一侧的字飞散 4 帧 → 约 1 秒重组变整齐 → 立刻做一次"预备"示威；只有最后一击才整个炸开 | 几何 4:14–4:16 |
| 读得出的意图 | 要偷某个字之前，身体里短暂拼出那个词（比如 `jump`）5 帧，再变回乱码 | 编程的代码高亮 |
| 得意 | 主角倒地时不追，在原地把刚吃的字抛起来转一圈 | 数学 4:11–4:14 |
| 害怕 | 变小、拉成一条细线贴地溜 | 数学 4:16 |

**攻击种类（随形态增加，能力本身不变）**
- 团：字带抽（一串字 2 帧伸出去）、扑上去吃。
- 人形：和主角一样的拳脚（用招式库），**每打中一下，打中的地方留一小块灰色乱码**；远程扔字。
- 巨人：踩、扫，吸整段代码。

### 2.4 电脑

- 主角掌控的标志：在手里 = 他占上风；脱手 = 危险；小蛇推回来 = 转折；结尾平静地托着 = 和解。
- 被撞飞、被踢飞时按物体飞（翻滚、落地滑），落地后屏幕上的代码还在。

### 第二幕：四个回合（0:40–3:30）

每个回合的模板（原片编程集 + 用户对打斗的意见）：
**乱码出招 → 主角用身体躲（连贯，2–4 秒）→ 拿到电脑打 1–2 秒（只改一处）→ 代码造出东西 → 主角用身体 / 小蛇 / 造出的东西打 3–5 秒（连贯）→ 乱码用"偷字"反击 → 电脑再次脱手。**

## 4. 打斗的设计要点（做之前每回合都对照）

1. **连贯**：每一段打斗写成"招 → 招"的链，上一招的收势位置 = 下一招的起点（招式库按这个接）。停只在回合之间。
2. **差一点比打中多**：躲的时候攻击在他离开 2–4 帧后才落到原位。
3. **主角越打越会**：回合 1 全靠躲和运气 → 回合 2 第一次用对招（跳过去顺势踹）→ 回合 3 让身体自己打 → 回合 4 连招。
4. **乱码的能力不变，主角的招在变**：观众只需要追踪主角的新招。
5. **悬念装置"偷字"用 3 次**（`jump`、`dodge`、整段 `def`），每次都是：它盯住 → 身体里拼出那个词 5 帧 → 代码里那个字悄悄变灰 → 下一次运行失灵。第三次由"偷一个字"升级成"吞一整段"。
6. **"预备"用 4 次**（0:33、1:00、1:32、4:05），第一次教观众，之后观众一看就紧张。
7. 镜头：回合内固定全景框住两方（间距 1.3–2.8H，脚在下三分线）；被打飞时 6–12 帧快速拉远；代码只露 1–2 秒。

## 7. 做的顺序和验收（设计定了以后）

1. **乱码造型三版静帧**（团 / 人形 / 巨人各一张，加"预备""盯住""打嗝"的关键帧拼图）→ 用户挑。
2. 乱码的动作条（预备、盯住、打嗝、爬、被打重组）→ 和原片的动作条并排对比。
3. 冷开场 + 第一幕（0:00–0:40）→ 体检 + 抽帧 → 用户本机渲染看。
4. 回忆镜头工具（调用上一集场景画指定时刻 + 灰度 / 暖色、暗角、黑边、颗粒）。
5. 回合 1 → 2 → 3 → 4 → 第三幕，每做完一段给用户看一次。

验收：体检 0 问题；连贯检查（`contact_check` 逐帧：打斗段两人不能同时停 > 4 帧）；构图检查（代码块面积 ≤12%、一屏 ≤4 组）——这两条体检要加。
