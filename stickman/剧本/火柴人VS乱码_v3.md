# 火柴人 VS 乱码（第三部，剧本 v3）

> v2（`火柴人VS乱码.md`）保留。v3 按用户对前 64 秒的意见重写开头和对手：
> 1. **探索要短**：上一集已经演过"探索"，这一集开头只留几秒的"玩"，马上进入麻烦。
> 2. **复杂的知识不在开头探索**：像 `upper()` 这种，参考片从来不在学习段讲；新知识直接在战斗里用出来，看到一个好玩、有创意的效果就够了。
> 3. **已有的东西要派上用场**：上一集的三节小蛇 `hi hi hi` 是这一集的核心道具（被吃、被救、当武器、结尾回报）。
> 4. **少造东西**：不再有满地的 5、7、便签、车厢、大 HI。画面里只有：他、电脑、代码、小蛇、乱码。
> 5. **对手的出场和"悄悄的影响"**按参考片重做（见下）。
> 6. **动作节奏**：每次发现不需要配一个完整动作；反应 0.3–0.5 秒就继续，不再用好几秒的镜头演"惊讶"；手够不着的东西不去抓。

## 对手：乱码是什么、从哪来

- **它是上一集那条无穷长蛇的残骸**。上一集他按 `Ctrl+C` 把正在输出的长蛇打断，蛇碎成字掉下来化成灰——**被打断、只写了一半的输出就是乱码**（技术上也说得通：半截的字节解码出来就是 `锟斤拷`、`�`）。对手是他自己造成的（参考片的模式），而且把两集串起来了。
- **能力只有一个，全程不变：碰到的字都会变成乱码，然后被它吸走**。字被吸走，它就变大。主角的代码、小蛇、他打出来的东西，都是字。
- **样子**：一团没有固定形状的乱码字（`锟 斤 拷 烫 屯 � Ã ¤ ÿ`……），一直在重新排列、变形，没有脸。灰白色，偶尔整块错位一下（像信号不好）。后面吃了他的 `jump()` 之后，学着他的样子拼成一个乱码火柴人（头是 `�`）。
- **观众怎么知道这条规则**：前 20 秒先让它**悄悄**动两次手脚（观众看得见，主角没注意），规则就立住了；之后打斗里一看到代码里有个字在闪，观众就知道要出事。

## 它怎么悄悄影响他

1. **开场**：他们从左往右走，远处身后（上一集长蛇碎掉的地方）地上一个 `�` 闪了 3 帧。小蛇停了一下，回头。他没注意。
2. **改小蛇**：他把上一集的代码 `while n < 3` 改成 `5`，小蛇多长出两节——最后一节飞过来的路上闪成 `h锟` 3 帧，才变回 `hi`。他没注意。
3. **jump()**：他回车的那一帧，`jump` 里的 `u` 变成了 `锟` → NameError 红光把他推开。他凑近看代码——又是好好的 `jump()`。挠头，再运行，这次跳了。
4. **吃小蛇**（出场）：小蛇的尾巴一节一节变成乱码……主角先吓得往后弹、跌坐（先演反应）→ 镜头拉远：一团乱码咬着蛇尾，**地上一串淡淡的乱码脚印一直通到画面左边**——它从上一集就一直跟着他们。
5. **打斗里**：他忙着打的时候，代码里的某个字悄悄闪一下（观众看到，他没看到）→ 下一次运行就失灵。这是全片反复用的悬念。

## 新的知识阶梯（学的都在战斗里用出来）

| 步 | 知识 | 怎么出现 | 效果 |
|---|---|---|---|
| 0 | `while n < 3` 改数字（上一集学的） | 开场把 3 改 5，小蛇长两节 | 小蛇是代码做的，改数字就能变长（之后当武器） |
| 1 | 函数调用 `jump()` | 开场被乱码坑一次，再跑一次就跳了 | 函数名 = 身体的动作 |
| 2 | `Ctrl+C`（上一集的招） | 乱码出现后他按 Ctrl+C——**没用**（它不是在运行的循环） | 老招失灵，危机升级 |
| 3 | `jump()` 当闪避 | 乱码甩过来，他敲 `jump()` 跳过去 | 第一招 |
| 4 | `while n < 10` | 小蛇变成 10 节的长鞭抽乱码；被碰到的那几节开始变乱码，他马上改回 3，小蛇缩回来，坏掉的那截掉在地上被吸走 | 第二招（也是"小蛇被救"） |
| 5 | 乱码偷偷改他的代码 | `jump` 里闪了一下 → 下一次闪避失灵，被打飞 | 回合结束 |
| 6 | （升级）乱码吃了 `jump`，拼成乱码火柴人 | 它学着他跳了一下 | 第一分钟结尾 |
| 7 | `for` 砌墙（回忆镜头 1） | 被逼到角落 → 闪回上一集 → 快打 | 墙 |
| 8 | `while True` + `if` 条件反射 | 身体自动闪 | 防守 |
| 9 | `def` 连招 + 参数 | `combo()`、`combo(3)` | 第一次打退它 |
| 10 | `try / except` | 每次报错被接住变成盾，反弹 | 终极 |
| 11 | 注释 `#`（回忆镜头 2） | 回忆揭开它的来历（上一集碎掉的长蛇）→ 不删，注释掉 → 最后一小团变回 `hi`，接到小蛇尾巴上 | 和解：小蛇变成四节 |

## 动作和节奏规则（这次的教训，也写进制作手册）

- 第二集起，开头的"玩"不超过 15 秒，20 秒内必须出事。
- 一个新知识只给一个效果，不给"发现 → 端详 → 摆弄 → 点头"整套表演。
- 反应：0.1 秒到位、定 0.3 秒、马上接下一件事。惊讶不单独占镜头。
- 手只抓得到的东西：要拿远处的东西，先走过去（或者干脆不拿）。
- 每一样新出现的东西都要在后面用到，否则不要造。

## 第 9 轮学习之后要改的地方（下次做画面时按这个改，先改造型和节奏，再往后做）

1. **乱码团的造型**（拆解 3.6）：要有清楚的外轮廓和一个最大最亮的核心字（`�`）；平时字整齐、慢慢绕核心转，只有吃东西 / 被打时才乱；被它碰过的字留下灰色痕迹（不是本体）。
2. **固定的预备动作**：每次大攻击前 缩 0.7 倍（7–13 帧）→ 1 帧弹到 1.2 倍 → 边缘抖 8–11 帧 → 出手；出手前完全静止。"吸字 + 打嗝"（核心闪一下被吃的字）每次吃东西都做。
3. **出场先污染后露身**：小蛇尾巴变乱码、闪约 1 秒之后，本体才从那里长出来（现在是同时出现）。
4. **电脑要脱手**（拆解 3.5）：乱码第一次扑过来就把电脑撞飞；主角先用身体躲 2–4 秒，再飞扑抢回来，趴着打 1–1.5 秒；小蛇可以把电脑叼回来。全段主角拿电脑的时间 ≤25%。
5. **用手直接拔字**：主角单手托电脑，空手伸进乱码团拔出一个字塞回自己的代码（比如把 `锟ump` 的 `锟` 拔掉换成 `j`），一次 1–2 秒。乱码被拔一块小一块。
6. **构图**（拆解 2.3）：代码块缩到全景最多 3 行、字高 0.15H，放在主角看的那一侧上方；揭示乱码时人和乱码放画面两头；动作段代码露 1–4 秒后让镜头带走。
