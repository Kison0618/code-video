# 第三部的对手：换一个（候选和设计理由）

> 用户看了乱码造型设计板："都是垃圾，它可以不是乱码，别的行不行，别的里面可以怎样表现出来？学习参考视频。"
> 这份稿子先总结原片的对手为什么成立、乱码为什么不成立，再给 4 个候选，每个都写清楚"它是什么、长什么样、怎么演、怎么打、怎么收场"。

## 1. 原片的对手为什么成立（依据：`研究/非人形对手_表演.md`、`参考片笔记_*.md`）

| | 编程集：笔记本 | 数学集：e^{iπ} | 几何集：高维多胞体 |
|---|---|---|---|
| 它是什么 | 主角自己的工具 | 主角自己算出来的 -1 的另一副面孔 | 几何的"下一个维度" |
| 观众认不认识 | 人人都认识电脑 | 学过的人认识，没学过也看得出是"一个符号" | 一看就是"一个形状" |
| 样子 | 一个现成的东西，一点没改 | 一个干净的白色字形，约 0.5H | 一个干净的白色线框，一直在转 |
| 怎么表达意图 | 光标在打字 = 在想；高亮 4–6 帧 = 扣扳机 | 字形朝向、变换写法 | 转到正面停一下；缩 → 弹 |
| 能力从哪来 | 它会写代码（和主角一样） | 它的数学性质（旋转、展开、自我替换） | 它会吃几何 |

**共同点**：
1. **对手本来就是这个世界里的东西**，而且是这一集主题的核心——不是另外发明的怪物。
2. **样子极简、干净、一眼认得出**：一个现成物体、一个字形、一个线框。小也看得清（e^{iπ} 只有 0.5H）。
3. **"表情"来自它本来就会做的事**：电脑会打字、字形会变写法、线框会转。不需要给它加眼睛和表情。
4. 能力 = 它的真实性质，所以观众看它打架的同时就在学东西。
5. 结局是理解它 / 和它共处，因为它本来就是主角世界的一部分。

**乱码为什么不成立**：乱码本身就是"没有形状、看不清"的东西，越做越像噪点，和第 2 条正好相反；"编码错误"对大多数观众太陌生，和第 1、4 条也不合。

## 2. 候选

### 候选 A：第二个光标 `_`（推荐）

- **它是什么**：编辑器里的光标。全系列每一集开场都是一个闪着的光标（编程集原片 0:00 也是），观众最熟悉。这一集出现了**第二个光标**——不是他的。
- **样子**：一条白色的下划线 `_`，和他的光标一模一样，只是**闪的节奏不同**。可以长大：从字那么大（0.15H）到一根横梁那么大。干净、一眼认得出，满足第 2 条。
- **怎么表达意图（全是光标本来就会做的事）**：
  - 闪得慢 = 平静、在观察；闪得快 = 兴奋；**停止闪烁、常亮 = 盯住**（全片最吓人的一刻就是它不闪了）。
  - 它移到哪个字后面 = 它在"看"哪里。
  - **选中（一段字变成高亮）= 瞄准**，正好就是原片"高亮 4–6 帧再开火"的规律。
  - 打字 = 它在说话；它可以打出 `hi`、`no`、`:)`。
- **能力 = 编辑器的真实操作**：选中、删除（Backspace 一个个吃掉字）、改字（把 `jump` 改成 `jmup`，所以 NameError）、复制粘贴（`Ctrl+V` 一下变出一排自己 = 分身）、撤销（`Ctrl+Z` 把他刚写的代码撤回去）。全是观众用过的操作，一看就懂，还能学到。
- **悄悄出手**：他写好的代码，后面多出一个不是他打的字。
- **打斗**：它在地上"打字"打出一排字当墙、当桥、当子弹；它能选中他的小蛇（高亮），然后一按 Backspace 吃掉一节；它能 `Ctrl+X` 把他脚下的字剪掉让他掉下去。
- **主角怎么赢**：用它的规则反过来——他也有光标；他学会选中、复制、撤销；最后 `try/except` 或者他用 `Ctrl+Z` 把它对小蛇做的事撤回来。
- **收场**：它原来是另一个想写代码的人（多人同时编辑）；最后两个光标一起打出一行字 `hi`，它的闪烁节奏和他的同步了。

### 候选 B：报错（Traceback）

- **它是什么**：每一集都在打他的那道红光——`NameError`、`IndentationError`。这一集，红光**不散了**，变成一个角色。来源就是他自己的错误，和数学集"自己算出的 -1"同一种关系。
- **样子**：一块干净的红色报错文字 + 下面一排 `^^^^`（Python 3.11 报错用来指错误位置的小尖号），尖号就是它的"牙"或"脚"。红色在全系列里只代表报错，观众一看就懂。
- **怎么表达意图**：`^^^^` 指向哪里 = 它在看哪里；它的文字会换（`NameError` → `TypeError` → `IndexError`），每换一种就是换一种攻击；它变长 = 一层层叠起来的 traceback（`File ... line 3`），越叠越大。
- **能力**：每种报错一个招式，都是真实的错误：NameError 让他的招式失灵、IndexError 让他抓空、TypeError 让两样东西撞出火花、RecursionError 让它自己复制成一座塔。
- **主角怎么赢**：`try / except` 把它接住、关进框里（`except` 就是笼子）。
- **收场**：他读懂了它在说什么——**报错是在告诉你哪里错了**。最后它的 `^^^^` 指着他代码里一个小错，他改掉，它变成他的向导。教育意义最强。
- **风险**：红色大块文字会比较"吵"；要控制只用一行字 + 尖号。

### 候选 C：None（空）

- **它是什么**：Python 里的 `None`——什么都没有。函数忘了写 `return` 就会得到它。
- **样子**：一个只有虚线轮廓的空盒子，或者一个淡紫色的 `None` 字（Python 关键字的颜色）。
- **能力**：碰到的东西都变成空的虚线轮廓（值被抹掉），小蛇被碰到一节就只剩虚线。
- **收场**：他给它写了 `return`——它第一次装进了东西。
- **风险**：概念有点抽象；"抹掉"和乱码的"吃"差不多，画面上的冲击力不如 A、B。

### 候选 D：他自己的分身（递归）

- **它是什么**：他写了一个调用自己的函数，造出一个**蓝色的自己**，那个自己又造出更小的自己……
- **样子**：和他一样的火柴人，只换颜色；越往后越小、越多。
- **能力**：和他一模一样的招式（招式库直接能用），打斗最好做；递归复制成大军；没有终止条件就 `RecursionError`，整座塔塌掉。
- **收场**：他给递归加上终止条件，最后只剩一个蓝色的自己，两个人并排坐着。
- **风险**：分身对手在打斗片里很常见，"代码味"最弱。

## 3. 推荐

**A（第二个光标）**，理由：
- 最符合原片的规律：本来就在这个世界里（每集开场都有）、样子极简干净、"表情"全部来自它本来就会做的事（闪烁节奏、移动、选中、常亮），不用另外设计。
- 能力全是编辑器操作（选中、删除、改字、复制、撤销），观众都用过，看打架就等于学操作。
- 和原片编程集最像但不重复：原片对手是整台电脑，我们的对手是电脑里的"另一只手"。
- 第三幕可以很温柔：两个光标一起打字。

B 是第二选择（教育意义最强：报错是朋友）。B 的"报错一层层叠"也可以和 A 结合：A 的光标改了他的字 → 产生报错 → 报错打他。

定了以后，原来设计稿 v4 的骨架（小蛇线、主角和电脑的关系、四个回合的结构、回忆镜头、构图规则）大部分保留，只把对手换掉。
