# 制作手册

每次做新片子先读这份。顺序不能乱：**内容 → 分镜 → 工具 → 画面 → 体检 → 渲染 → 声音时间表 → 交付**。

## 1. 内容（剧本）

写在 `剧本/<片名>.md`，是唯一依据，画面、镜头、声音都按它来；改内容先改剧本。剧本里要有：

- **一句话**：讲一个什么故事
- **知识表**：主角每一步学到什么、怎么学到的（看得见的结果）。每一步只多知道一点；结果必须是实物（字出现、变红、掉下来、堆起来）
- **节拍表**：时间 / 画面 / 内心 / 镜头 / 声音 五列
- **结构**：三幕，起（好奇、摸索）→ 承（小成功、玩上瘾）→ 转（玩过头、危机）→ 合（解决、喘口气、一个小笑点收尾）

内心过程（拆解 3.1 节）：注意到 → 停住看 → 情绪姿势 → 小心试探 → 得出结论 → 下一步。"停住看"不能省。

## 2. 分镜草图

动手前用生图模型（gpt-image-2.5，密钥在仓库外 `~/.config/kedaya/key`）按节拍表出 3×3 分镜草图，核对景别和画面是否成立，存到 `storyboards/`。只用来确认，不进成片。

## 3. 工具（都在 `render/src/`）

| 要做的事 | 用什么 |
|---|---|
| 角色动作 | `actor2.js`（意图 + 弹簧 + IK）、`moves.js`（走、跑、跳、滑铲、跪、被打飞、爬起来……）、`acting.js`（注意到、看、托腮、挠头、吓一跳、戳、反应过来、想到主意、点头） |
| 时间、打击、音效、镜头 | `director.js`：音效一律写动画时间、打击登记停顿帧、镜头写意图（景别 + 看谁），最后 `finalize` 统一换算 |
| 代码界面 | `code.js`：打字、删除、选中替换、运行、报错、光标、被戳会抖 |
| 物体 | `phys.js`：掉落、弹跳、被踢飞；`Pile` 字堆（一层层堆起来、会滑成小山、被撞走会离开） |
| 打击感 | `impact.js`：五档打击（停顿帧、震屏、推镜、反色、冲击波……） |
| 体检 | `tools/qa.js`：不渲染，逐帧查出画、瞬移、角度突跳、代码被切、远景太久、音效 id 缺失 |
| 声音时间表 | `tools/cue_sheet.js` → `audio/时间表/<场景>.md` |
| 动作对照原片 | `analysis/ref_pose.py`（从原片提取骨架）+ `tools/move_frames.js`（把动作按原片大小渲染出来量化对比） |

## 4. 画面

- 一幕一幕做：写一幕 → `node src/tools/qa.js` → `node src/preview.js` 抽关键帧看 → 改 → 下一幕
- 镜头规则（拆解 2.1 节）：看反应推近、看规模拉远；在节拍上推拉、节拍之间稳住；大事件先远后近；跟拍给威胁那一侧留空间；镜头里的代码要么完整、要么完全不拍
- 跑步用 `run`（原片实测步态），不要自己编

## 5. 常见毛病（体检会报的、肉眼才看得出的）

| 毛病 | 原因 / 解决 |
|---|---|
| 身体整圈倒转 | 前倾目标跨了一整圈；`lean()` 已经自动就近取，不要绕过 |
| 胯或脚瞬移 | 远距离移动没给时长（弹簧会甩过去）：`kneel({ dur })`、`hip(t, p, dur)`；脚从"跟着身体"切回"踩地"已自动从实际位置过渡 |
| 手臂不见了 | 手的参数传了函数但模式不支持；`free / pose / local / world` 都支持函数 |
| 埋不住人 | 字堆要画实心轮廓（字后、人前），字要够密 |
| 钻出来后字悬在半空 | 炸开要按整列算，不按距离；被撞走的字会自动离开字堆 |
| 落地声响成一片 | 很多字一起落地时用 `word_rain`，单个 `tick` 要稀疏 |
| 代码被镜头切一半 | 镜头 `on` 里加上代码的范围，或者让镜头完全不拍代码 |

## 6. 声音

需要的声音写进 `audio/音效需求.json`（`audio/gen_req_md.py` 生成 md），每个场景导出时间表。代码合成的只是占位。

## 7. 交付

渲染 → 抽帧看一遍 → 时间表 → README 补一段 → 提交推送到工作分支 → 把成片和要点发给用户。
