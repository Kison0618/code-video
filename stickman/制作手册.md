# 制作手册

每次做新片子先读这份。顺序不能乱：**内容 → 分镜 → 工具 → 画面 → 体检 → 渲染 → 声音时间表 → 交付**。

## 1. 内容（剧本）

写在 `剧本/<片名>.md`，是唯一依据，画面、镜头、声音都按它来；改内容先改剧本。剧本里要有：

- **一句话**：讲一个什么故事
- **知识表**：主角每一步学到什么、怎么学到的（看得见的结果）。每一步只多知道一点；结果必须是实物（字出现、变红、掉下来、堆起来）
- **节拍表**：时间 / 画面 / 内心 / 镜头 / 声音 五列
- **结构**：三幕，起（好奇、摸索）→ 承（小成功、玩上瘾）→ 转（玩过头、危机）→ 合（解决、喘口气、一个小笑点收尾）

内心过程（拆解 3.1 节）：注意到 → 停住看 → 情绪姿势 → 小心试探 → 得出结论 → 下一步。"停住看"不能省。

## 2. 分镜草图

动手前用生图模型（gpt-image-2.5，密钥在仓库外 `~/.config/kedaya/key`）按节拍表出 3×3 分镜草图，核对景别和画面是否成立，存到 `storyboards/`。只用来确认，不进成片。

## 3. 工具（都在 `render/src/`）

| 要做的事 | 用什么 |
|---|---|
| 角色动作 | `actor2.js`（意图 + 弹簧 + IK）、`moves.js`（走、跑、跳、滑铲、跪、被打飞、爬起来……）、`acting.js`（注意到、看、托腮、挠头、吓一跳、戳、反应过来、想到主意、点头） |
| 时间、打击、音效、镜头 | `director.js`：音效一律写动画时间、打击登记停顿帧、镜头写意图（景别 + 看谁），最后 `finalize` 统一换算 |
| 代码界面 | `code.js`：打字、删除、选中替换、运行、报错、光标、被戳会抖 |
| 物体 | `phys.js`：掉落、弹跳、被踢飞；`Pile` 字堆（一层层堆起来、会滑成小山、被撞走会离开） |
| 打击感 | `impact.js`：五档打击（停顿帧、震屏、推镜、反色、冲击波……） |
| 会砸到人的东西 | `phys.js` 的 `collide: actor`：头、身体、四肢都算碰撞，按相对速度弹开，接触记在 `body.contacts`。做法：写完动作 → `hero.simulate(dur, { sfx: false })` 预演 → 生成物体 → 按砸到头的时刻加 `hero.bonk(t)` → 正式 `finalize` → 再生成一次 |
| 一串跟着走的东西（蛇、队伍） | `snake.js`：身体 = 头走过的路；`spline` 写头的路径，`pieces` 拼接；`bob` 让头原地晃（不进轨迹）；`max` 限制节数 |
| 键帽、代码标签 | `props.js` 的 `keyCombo`（按组合键时在电脑上方弹出，不切镜头）；`code.tag`（代码旁边的 True / False / 变量值）；`code.fadeOut`（中途淡出再淡入） |
| 站到台子上 | `jump({ gy })`：落在多高的台子上 |
| 打斗 | `fight.js`：`actor.move(t, '招式', { to: 对手 })`（招式在 `analysis/fight_moves.json`，24 帧关键帧；`to` 会自动补步子够到对手）；`exchange(D, beats, fx)` 一拍一拍排攻防（攻方招式、守方反应、等级、结果字形），守方的闪 / 挡会自动提前起手；`FightFX` 画 1 帧光 + 火花 + 字形；`drawWeapon` 画手里的兵器和 1 帧拖影。演示 `SCENE=fight`（`scene_fight_demo.js`）、试做 `SCENE=duel1`（`scene_duel1.js`，击剑式，被用户否了）、`SCENE=duel2`（`scene_duel2.js`，动漫刀剑，第 8 轮）。第 8 轮 key 新字段：`wa` 剑角、`wl` 透视缩短、`h` 前手 [胯前, 离地]、`g2` 双手握、`turn` 转身、`slide` 脚贴地滑、`fr` 空中脚按身体写；没写的脚够不着时自动跟一步；`drawWeapon` 的 `arc`（月牙拖影）/ `arcFrom` / `trail`；镜头 `D.follow` 平滑跟拍。招式 key 的 `hipY` 是胯离地的绝对高度（架势用，重复调用不会越来越低）；`F` / `B` 手的位置是**世界方向**（不随前倾转），兵器沿"肘 → 手"方向；`move(t, 名, { reach })` 覆盖出手距离；`exchange` 每拍写 `tip: 剑长` 让打击点落在兵器尖，并登记到 `D.fights` |
| 刀剑（单手） | `fight.js`：`actor.blade`（剑柄 / 护手 / 拳头 / 剑指 / 剑穗，刀单刃翻刃，肘自动翻）、`FlyBlade`（兵器脱手、断刀头）、`blade.broken`（断刀）；慢镜头 `clock.slow`。例子 `scene_blade1.js`，设计稿 `剧本/刀剑短片_blade1.md` |
| 打斗距离 | `tools/contact_check.js`（场景导出 `fights`、`weaponLen`）：逐拍查剑尖越过躯干、到身体距离、剑碰剑、剑尖插地、站太近、碰剑在身前、闪避"差一点"，给建议 reach；逐帧查架势太低；第 8 轮加：闪避按整条剑身算、守方挡剑反求接触帧的 `h` / `wa`、碰点在两把剑的哪一段，逐帧查剑尖插地、手脚够不着、锁剑段两把剑分开（场景导出 `locks`）、打斗段两人同时不动 > 4 帧（停顿）。`tools/fight_probe.js 30-48`：打印那几帧两人的胯、手、剑尖、剑角、脚。`tools/hand_for.js`：想让剑尖到某处，手放哪 |
| 体检 | `tools/qa.js`：不渲染，逐帧查出画、瞬移、角度突跳、代码被切、远景太久、音效 id 缺失、**运行时的代码不是合法 Python** |
| 声音时间表 | `tools/cue_sheet.js` → `audio/时间表/<场景>.md` |
| 动作对照原片 | 学习闭环（`动作设计.md` 第 3、6 节）：`analysis/ref_track.py` 逐帧条 + 每帧 d → `ref_grid.py` 手量 → 写进 `fight_moves.json` → `tools/move_seq.js` 按 24fps 渲 → `analysis/ref_compare.py` 和原片同帧并排。快速看：`analysis/ref_strip.py`（原片或成片任意一段拼成动作条）+ `tools/move_frames.js 动作 out.png`（我们的动作，同样格式；`fight_moves.json` 里的招式也能直接出）；`ref_pose.py` 提骨架（只适用黄色实心头）。实测结论在拆解 3.1.1 |

## 4. 画面

- 一幕一幕做：写一幕 → `node src/tools/qa.js` → `node src/preview.js` 抽关键帧看 → 改 → 下一幕
- 镜头规则（拆解 2.1 节）：看反应推近、看规模拉远；在节拍上推拉、节拍之间稳住；大事件先远后近；跟拍给威胁那一侧留空间；镜头里的代码要么完整、要么完全不拍
- 跑步用 `run`、走路用 `walk`（都是原片实测步态），不要自己编
- 动作节奏：**快动作 + 长停顿**。反应（吓到、被砸、泄气）1–2 帧到极限、定住 0.2 秒、再回来，然后定住看；不要让人一直慢慢晃
- 打斗（拆解 3.5 + 第 8 轮用户意见）：打中不停帧不震屏；出招 1–2 帧、预备是它的 2–3 倍、收招 5–6 帧；**打架中间不停**（上一招收势 = 下一招预备，"停"换成锁剑、滑退这种仍在动的段落；拆解里"快拍之后一定停"作废）；**动漫刀剑不是击剑**（双手握、`wa` 大弧线、透视、转身）；"差一点"比打中多；回合内镜头不乱晃（duel1 固定全景；duel2 用 `D.follow` 平滑跟拍两人和剑尖），被打飞时快速拉远。新回合先在 `SCENE=fight` 里排，看顺了再搬进正片
- **刀剑打斗（第 10 轮）**：按"字"拆招——每拍用剑法 / 刀法的一个字化解（挂、截、点、崩、绞、云、压 / 劈、扫、撩、拦、盖），化解完兵器停的位置就是下一招起点；刀招写满、剑招写小；30 秒里要有几段"静"（对峙、蓄势、背对背）；插段用一个偏移量管后面所有帧号
- **做任何快动作（打、扑、摔、吓、撞）之前先读 `动作设计.md`**：按七个问题出设计稿（招牌姿势、收紧、节奏表、先后、曲线、反应和镜头），写成 24fps 的关键画，`move_seq.js` + `ref_compare.py` 验收后再放进场景
- 新招式：在 `fight_moves.json` 里写关键帧 → `move_frames.js 招式名` 出动作条、`move_seq.js` 出 24fps 序列和原片对照 → 放进演示
- **构图（拆解 2.3）**：代码行距 0.3H、字高 0.15H，跟世界缩放；全景最多 3 行、面积 ≤12%；放在人看的那一侧上方、不压人；输出字 0.05–0.1H；一屏最多 4 组东西；动作段代码露 1–4 秒后让镜头带走
- **主角和电脑（拆解 3.5）**：打斗里主角拿电脑的时间 ≤25%；每 5–10 秒换一次人和电脑的关系（出事 → 电脑脱手 → 捡回来换姿势）；一次打字 ≤2.5 秒只改一处；站着用前臂托、单手打，空手做表演
- **没有脸的对手（拆解 3.6）**：轮廓 + 核心、平时整齐、固定预备（缩 → 弹 → 光晕）、出手前静止、被打局部散开再重组
- **剧情节奏（第三部开头返工的教训）**：系列第二集起，开头的"玩"不超过 15 秒、20 秒内出事；复杂知识不探索，直接在打斗里用出来；一个新知识只给一个效果；新造的东西必须后面用到（优先用上一集留下的）；对手先悄悄出手让观众看见规则，再正式出场
- **动作节奏**：反应 0.1 秒到位、定 0.3 秒就接下一件事，惊讶不单独占镜头；不是每个发现都要配一个动作；手只抓够得着的东西（远的先走过去）
- 新动作先用 `move_frames.js` 出动作条，和原片的动作条并排看，再放进场景

## 5. 常见毛病（体检会报的、肉眼才看得出的）

| 毛病 | 原因 / 解决 |
|---|---|
| 身体整圈倒转 | 前倾目标跨了一整圈；`lean()` 已经自动就近取，不要绕过 |
| 胯或脚瞬移 | 远距离移动没给时长（弹簧会甩过去）：`kneel({ dur })`、`hip(t, p, dur)`；脚从"跟着身体"切回"踩地"已自动从实际位置过渡 |
| 手臂不见了 | 手的参数传了函数但模式不支持；`free / pose / local / world` 都支持函数 |
| 埋不住人 | 字堆要画实心轮廓（字后、人前），字要够密 |
| 钻出来后字悬在半空 | 炸开要按整列算，不按距离；被撞走的字会自动离开字堆 |
| 落地声响成一片 | 很多字一起落地时用 `word_rain`，单个 `tick` 要稀疏 |
| 代码被镜头切一半 | 镜头 `on` 里加上代码**最终**的范围（打字还没打完时取 `codeBox` 会按半截代码取景）；或者 `code.fadeOut` 让它暂时退场 |
| 屏幕上的代码语法不对 | 选中替换之后光标停在中间，接着敲新行会插进括号里：敲新行前先 `code.cursor(t, 文本长度)`；体检会查 |
| 从高处被打飞，落地后被拽回去 | `launch` 已经从落地点开始滑（旧版本从起飞前的目标插值） |
| 一串东西挤成一团 | 头的路径来回折返了；原地晃用 `bob`，不要写进路径 |
| 打斗时两个人叠在一起 / 胯瞬移 | 招式的起点要取**当前实际位置**（`pathNow` / `hipNow`），不要用旧目标；`keys()` 已经这样做 |
| 出招够不着对手 | `move(t, 招式, { to: 对手 })` 自动按距离补步；招式要有 `reach` |
| 出招后两脚劈叉 | 没写关键帧的那只脚要跟一步（`follow`，`move` 已自动加） |
| 镜头规律 | 拆解 2.2：开场空、全景为基准、变多才拉远、大远景只当标点、近景只给反应 |

## 6. 声音

需要的声音写进 `audio/音效需求.json`（`audio/gen_req_md.py` 生成 md），每个场景导出时间表。**音效由用户设计**（第 7 轮定）：我只写需求清单（时间点、现用 id、想要什么感觉，例子见 `剧本/打斗试做_duel1.md`），不自己合成；代码合成的只是占位。

## 7. 交付

（第 7 轮起渲染在用户本机：交付渲染命令 + 看片清单）渲染 → 抽帧看一遍 → 时间表 → README 补一段 → 提交推送到工作分支 → 把成片和要点发给用户。
