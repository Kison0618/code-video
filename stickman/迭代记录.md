## 2026-10-20 第 11 轮：剑决定手 + 开场重做（blade2）

**用户意见**："黄色人的手的位置不对，开头的两个人分别舞剑太尬了，而且后面动作其实也不流畅，思考问题所在，更重要的是如何去优化创作的技术"。

**问题在哪（量出来的，`tools/wrist_check.js`）**
- **手和剑是两个各写各的数**：key 里 `h`（手在哪）和 `wa`（剑指哪）分开手写，中间的腕角（前臂和剑的夹角）没人管。blade1 主角 158/719 帧、强者 293 帧腕角 > 60°——剑像粘在手腕上转，不是握在手里。肘只有 ±1 两档、迟滞又大，该翻不翻。
- **2D 没有深度**：剑转到身体另一侧时照样画在前面，主角 77 帧剑穿过头（剑花那段最明显）。
- **每个 key 都"到位 → 停 → 再起"**：默认缓动 `out` 在每个 key 速度归零，剑尖速度一帧一帧突变（顿挫 29 / 48 次）。
- **开场是轮流表演**：强者缠头裹脑时主角死站，主角剑花时强者死站（独舞 f5–16、f28–45）。

**做了什么（`fight.js`，旧场景结果逐字节不变）**
- **剑决定手**（`actor.blade.solve`）：剑的线是设计意图不动，手沿着剑线滑（≤ 0.2H）、肘向在 −1…1 连续选（`bestBend`），让腕角 ≤ 45°。接触帧（攻方 `hit`、守方挡的 `ready` 帧）手不滑，碰点不变；剑尖朝下时手不往剑尖滑（防插地）。key 级 `wr` 指定腕角、`wr: null` 跳过，招式级 `"solve": false`。
- **自动前后**（`actor.blade.autoBehind`）：剑身穿过头、或剑尖朝后且穿过躯干 → 这一帧剑画在身后。
- **剑路默认样条**（`actor.blade.thru`）：手和剑（F / B / wa / wl）没写 `e` 的中间 key 用保单调的 Catmull-Rom 穿过，最后一个 key 才 `out` 收住；胯和身体不改（招式常被下一招中途接走，胯换样条会让间距变）。招式级 `"thru": false`。
- **新场景 `SCENE=blade2`**（`scene_blade2.js`，blade1 不动）：三个开关全开；开场改成两人从第 1 帧就是架子、同时动——一起上步 → 强者虚晃 / 主角坐身压剑 → 主角点腕虚招 / 强者立刀退半步 → 稳住 → 冲上来时主角沉身收剑。新招 `ready_jian_c` `ready_dao_c` `edge_h_c` `feint_f_c` `flinch_h_c` `feint_h_c` `flinch_f_c` `brace_h_c`；镜头开场不再切主角中景。
- **新工具 `tools/wrist_check.js`**：逐帧量腕角 > 60°、剑穿头、手够不着、剑尖速度突变、独舞（一人动另一人完全不动）。

**结果（blade1 → blade2）**：腕角 > 60° 主 158→28、敌 293→32；穿头 77/10→0；顿挫 29/48→20/36；开场独舞没了（全片 75/68→60/51，剩下的是中段一方出招前另一方等的 1–3 帧）。`contact_check` 28 拍全过，`qa` 0 问题；blade1 / duel1 / duel2 检查结果和改之前一字不差。

**学到了什么（会改变以后做法的）**
- **约束写进求解器，不写进每一招**：82 招一招一招改手位改不完也会再错；"剑定、手跟"一条规则全片生效。以后加身体约束都先问：能不能变成求解器的一条规则 + 一个量它的检查工具？
- **先有量的工具再改**：凭看片说"不流畅"改不动；量成腕角、穿头、顿挫、独舞四个数，才知道问题在哪、改了有没有用。
- **样条要保单调**：普通 Catmull-Rom 在转折 key 会冲过头（剑尖插地）；转折点斜率取 0。
- **两人戏要互相反应**：一个人动的每一下，另一个人都要有反应（哪怕只是重心一坐、剑尖一压）。"亮相"在对打片里不如"试探"。

**留下的问题**
- 顿挫还剩 20/36 次，大多是出招起手（从静到快本来就是一下）；要看片判断是不是还嫌"卡"。
- 中段独舞的 1–3 帧（等对方出招）可以加"预判"小动作，这一轮没做。
- 还没看过视频，渲染在用户本机。

## 2026-10-19 第 10 轮：持剑画法 + 30 秒刀剑短片 blade1

**用户意见**："火柴人持剑，手部那里持剑，得注意一下，拿剑的动作等。接下来需要你继续设计动作。你是中国的顶尖武术指导设计大师。来设计这动作，接下来去做 30s 短片吧，先做带武器的比如刀剑的就可以"。（远端另一个会话已经把"学参考片三块"记成第 9 轮，所以这一轮是第 10 轮。）

**做了什么**
- **持剑画法**（`fight.js`"持剑""刀剑的画法"两节，`actor.blade`）：剑柄、护手、剑身（剑脊、收尖）/ 刀身（单刃、宽头、微弯，刃朝挥动方向自动翻刃）、握着剑柄的拳头、剑指、剑穗；肘按剑角自动翻（`gripGrid`，3 帧换过去，`rig2.js` 的 IK 支持小数 bend）；`behind` 让刀画在身后；`FlyBlade` 做兵器脱手（磕飞、插地、踢起来、接住、断刀头飞出去再掉下来）；断刀（断口、拖影只到断口）；`Clock.slow` 慢镜头。
- **新场景 `SCENE=blade1`**（`render/src/scene_blade1.js`，29.99 秒，设计稿 `剧本/刀剑短片_blade1.md`）：亮相对峙 → 第一回合 13 拍 → 力劈华山磕飞剑 → 空手三连躲 → 踢剑空中接剑 → 反击五拍 → 连环六拍 → 错身斩断刀 → 刀头落下吓一跳 → 抱拳礼。招式库加 82 个 `_b` 招（单手剑 / 单手刀）。
- **音效需求**：11 个新 id（`sword_whoosh`、`sword_clang`、`sword_scrape`、`blade_heavy_clang`、`sword_spin`、`sword_stick`、`sword_slam`、`sword_kick`、`sword_catch`、`blade_break`、`whistle_fall`）写进 `audio/音效需求.json`，`sfx.py` 先用合成音占位（做好放进 `samples/<id>/` 就替换）；拿刀剑的人挥动自动用 `sword_whoosh`、刀剑相碰自动用 `sword_clang`。时间表 `audio/时间表/blade1.md`。
- 自查：blade1 `qa` 0 问题、`contact_check` 28 拍全过（只剩 11 个单帧脚够不着，都在空中 / 起步）；两人逐帧位移都在体检阈值内；duel2 / duel1 / fight / garble2 `qa` 仍 0，loop2 仍 10，duel2 `contact_check` 全过。看了约 15 帧关键帧。

**学到了什么**
- **像不像"握着"剑看三处**：剑柄 + 护手（手握在柄上，不是剑从手指尖长出来）、肘跟着剑翻（剑举过头肘不翻，腕子就折成 150°）、空着的手有事做（剑指）。
- **肘翻过去要用 3 帧**，按"腕角 + 滞后"选（超过 105° 且翻过去能小 30° 才翻，回到 60° 以内才翻回来），硬切 1 帧像手臂折断。
- **刀是单刃**：刃朝挥动方向，上撩要翻刃；翻的那 1–2 帧刀变窄，自然就像转了刀。
- **写过 `hipY` 的招，后面的 key 也要写 `hipY`**：只写 `hip` 的 key 会回到招式开始的高度，胯会塌下去再弹回来。这一轮合并 `_b` 招时自动补了（57 处）。
- **中国武术的拆招**比动漫刀剑多一层"字"：每一拍用剑法的一个字（挂、截、点、崩、绞、云、压……）化解，化解完剑停的位置就是下一招的起点——比单独设计每一招快得多，也天然连贯。
- **刀剑不对称更好看**：刀招写满（举过头、甩到身后、大步），剑招写小（近、快、先动脚）；"刀看手、剑看走"。
- **30 秒要有"静"**：对峙半秒、蓄势、背对背、跪下后——静的段落让快的段落显得更快。场景里用一个偏移量 `S1` 管后面所有帧号，插一段只改一处。
- **慢镜头不影响判断**：`clock.slow` 只改真实时间和动画时间的换算，接触、音效都写动画时间，不用改。

**留下的问题**
- 没看过视频：对峙半秒静止会不会太死、第一回合 13 拍 4 秒会不会太快、4 个慢镜头会不会太多、结尾笑点的时间，都要用户看片后定。
- 风格：这一轮偏中国武术（单手剑、剑指、抱拳礼），duel2 偏动漫（双手、大弧线）；要看用户更喜欢哪种，或者正片里两种都用。
- 单手 `_b` 和双手 `_a` 两套招式并存；以后正片的打斗可以从两套里挑。

## 2026-10-19 第 8 轮：动漫刀剑打斗 duel2（按用户对 duel1 的意见）

**用户意见**（看 duel1）："感觉不够连贯和流畅；打架中间是没有停顿的；可以设计更好的动作，他们又不是击剑，你做成了击剑的样子，而不是正常动漫用刀剑打架的样子。"

**做了什么**
- 新场景 `SCENE=duel2`（`render/src/scene_duel2.js`，7.48 秒，设计稿 `剧本/打斗试做_duel2.md`）：对峙 → 拖刀对冲撞 X → 六拍连续攻防（袈裟斩 / 反劈 / 突刺 / 横斩 / 上撩 / 唐竹，每拍换攻方）→ 锁剑较劲 14 帧 → 推开滑退 → 跳劈劈地 → 燕返し磕飞剑 → 回转斩打飞 → 跪滑时打 `sword.len *= 3` → 巨剑上撩打飞空中的强者 → 两人都躺着。duel1 不改。
- 招式库加 30 个 `_a` 招（共 88 招），双手握剑，每招"说明"写了要点和数值。
- `fight.js`：key 新字段 `wa`（剑角，和前臂无关）、`wl`（透视缩短）、`h`（前手 [胯前, 离地]）、`g2`（双手握，自动算后手）、`turn`（招式里转身）、`slide`（脚贴地滑）、`fr`（空中脚按身体写）；没写的脚够不着时自动跟一步；叠招时后一招接管的脚作废前一招之后的落地（duel1 / fight 的脚因此更稳：够不着的帧 116 → 91、80 → 73）；`drawWeapon` 的月牙拖影 `arc`、`arcFrom`、`trail`。`actor2.js` 转身压扁不再要求 `step`；`director.js` 加 `D.follow` 平滑跟拍。
- 工具：`contact_check.js` 升级（闪避按整条剑身算；挡剑反求守方接触帧的 `h` / `wa`；打印碰点在两把剑的哪一段；逐帧查剑尖插地、手脚够不着、锁剑段两把剑分开、打斗段两人同时不动 > 4 帧）；新 `fight_probe.js`（打印某几帧两人的胯、手、剑尖、剑角、脚）。
- 自查：duel2 `contact_check` 12 拍 + 逐帧全过，`fight_probe` 0–180 帧无 ✗，`qa` 0 问题；duel1 / fight / garble2 的 `qa` 仍是 0。看了约 40 帧缩略拼图，修了：结尾镜头太远（`wide` → `full` + fit）、后仰闪时两把剑共线像碰剑、跳劈时主角的剑和劈下来的剑交叉、巨剑变长那帧扫出一大片灰。**没渲染视频**。
- 音效需求：新声音 `sword_clang`、`sword_scrape`、`sword_slam`、`sword_grow`（现在用占位 id），时间表 `audio/时间表/duel2.md`。

**学到了什么**
- **像不像击剑，根子在"剑沿前臂"**：剑只能顺着前臂伸出去，就只能刺；动漫刀剑要剑角单独写、双手握、手在身前、靠转腰和步子出力。
- **"快拍之后一定停"不能照搬**：那是原片统计，用户要的是不停。连贯的关键是**上一招的收势 = 下一招的预备**（剑停在哪儿下一招就从哪儿起，守方反应收在他下一招的起点），停换成仍在动的段落（锁剑、滑退、跪滑）。
- **碰剑碰在剑的强弱处**（攻 70–85% / 守 25–50%）才像真格挡，也自然把碰点放在两人之间。
- **长剑和地面**：手高 + 剑长 × wl × sin(wa) ≥ 0 每帧都要满足；1.65H 的剑不能贴地扫，用"指向镜头"的透视绕过去。
- **逐帧检查比逐拍检查重要**：逐拍全过时，逐帧还查出了手够不着（停在半路）、腿被拖直、锁剑时两把剑分开、两人同时停住——这些正是"不连贯"的来源。duel1 用新检查跑出 9 处（停顿 7 段、插地、够不着），正好对上用户的意见。

**留下的问题**
- 没看过视频：60fps 插值还是 `STEP=24` 一拍一更好、六拍的速度、锁剑时长、跪滑和打代码同时进行会不会太挤，都要用户看片后定。
- duel1 在新的逐帧检查下有 9 处问题，保留不改（作对比）。

## 2026-10-19 第 7 轮：自己设计一段打斗（试做 duel1）

**用户要求**：用学到的方法自己设计一段打斗。中途定了两条新规矩：渲染和合成交给用户本机（沙盒只做设计、代码和体检）；音效统一由用户设计，我只写需求。

**做了什么**
- 按七个问题设计了约 14 秒的 `SCENE=duel1`（设计稿 `剧本/打斗试做_duel1.md`）：两串攻防（4 拍被化解 + 1 点；劈空砸地 + 点脑门）→ 被挑飞 → 爬起来写 `sword.len *= 3` → 剑一帧变长 → 一刺打飞强者 → 举剑往后倒，两人都躺着。整段 24fps 一拍一，开了 `step` / `smear: false` / `turn`，角色 `noise: 0`。
- 招式库加 22 个 `_d` 招（共 58 招），每招"说明"里写了七问的答案和数值来由。
- `fight.js`：`hipY`（胯离地的绝对高度）、起点胯按"脚够得着"修正、招式第一帧手的过渡不超过第一个 key、`o.reach` 覆盖、`tip`（打击点在兵器尖）、每拍登记到 `D.fights`；`actor2.js` 的 `hand` 加 blend 参数。
- 新工具：`tools/contact_check.js`（逐拍查剑尖越过躯干、到身体距离、剑碰剑、剑尖插地、剑身扫中位置、站太近、碰剑要在身前、闪避要"差一点"，给建议 reach；逐帧查"架势太低"）、`tools/hand_for.js`（想让剑尖到某处，反求手位和能不能做到）。
- 自查：`contact_check` 10 拍全过，`qa` 0 个问题；`fight`、`loop2` 回归不变（0 / 10 个问题）；只看了 12 帧缩略拼图，**没渲染视频**。

**学到了什么**
- **"架势偏低"的根因是比例**：`fence_guard` 从橙色角色量来，两脚分开 0.55H；黄色骨骼腿只有 0.44H，后脚够不着，IK 把胯压到 0.15H。架势要按腿长算脚距（离胯 < 0.97 × 腿长）。原片的 `dodge_back` 每用一次胯低 0.04H，打几拍人就越蹲越低——架势用绝对高度 `hipY`。
- **手的 F / B 是世界方向**，不随前倾转；剑沿"肘 → 手"方向，肘永远在肩–手连线的下后方，所以手高于肩时剑尖不可能朝下。想要某个剑的角度先用 `hand_for.js` 算。
- **1 帧打到的招，手也必须 1 帧到位**：招式第一帧手默认 0.1 秒过渡，会让手晚到 2 帧（打中时剑还在半路）。
- **距离要量，不能估**：reach 含兵器长，接触间距 = reach − 招式自己在接触帧的胯前移；碰剑要两把剑成 X、碰在身前，所以比"闪开"站远约 0.3H；"差一点"是剑尖离身体 0.03–0.3H。全靠 `contact_check` 逐拍校。
- 强弱悬殊的写法：强者动的部位逐级变多（手腕 → 手臂 → 迈一步），第一次迈步 = 第一次认真。

**留下的问题**
- 等用户本机渲染看片：节奏、一拍一观感、架势高度、间距和碰剑、笑点。
- 打代码时强者在画面右边被切一半；`SCENE=fight` 演示片还用 `fence_guard`（胯被压低）。
- 音效：需求清单在设计稿里（剑碰剑、剑变长那一声最要紧），等用户设计。

## 2026-10-19 第 6 轮：动作的设计方法和实现方法

**和第 5 轮的关系**：两轮同时进行、各自提交；第 5 轮学"打斗怎么编排"（招式库、`exchange`、回合节奏），这一轮学"单个动作怎么设计、怎么做出来"。合并时招式库保留第 5 轮的 33 招，加上这一轮的 `fence_guard`、`lunge_step`、`uppercut_d`（共 36 招）；打击感以第 5 轮实测为准（打中不停帧不震屏），`动作设计.md` 已按它改。

**做了什么**

- 以前"原片停顿时也在微动"的说法不对：动作期间每帧都变，但情绪点上的定格是完全不动的。
