# 拆解：火柴人 VS 系列（Alan Becker）

素材：`claude专用` 分支 `reference-videos/火柴人系列/` 的 4 集。

| 集 | 时长 | 主角 | 世界 | 适合用代码复刻的程度 |
|---|---|---|---|---|
| 火柴人 VS 编程（Coding） | 8:24 | 黄色实心头 + 笔记本 | Python 解释器：敲代码 → 运行 → 结果变成实物 | ★★★★★ 最适合，也和我们"代码视频"的定位最贴近 |
| 火柴人 VS 数学（Math） | 14:02 | 橙色空心头（TSC） | 白色算式、数轴、单位圆、复平面 | ★★★★★ 纯矢量 + 白字 + 少量发光 |
| 火柴人 VS 几何（Geometry） | 9:16 | 橙色空心头 | 金色发光的线段、多边形、3D 线框多面体 | ★★★★ 发光、能量、线框 3D 都能写，爆炸段很吃后期 |
| 火柴人 VS 物理（Physics） | 16:08 | 橙色 + 戴牛仔帽的白描边角色 | 星空、太阳、黑洞吸积盘（大量照片 / 渲染素材） | ★★ 背景依赖写实素材，不优先 |

下面的数字都是从 1080p 原片里量出来的。

## 1. 画面规格

### 1.1 底色与"地面"
- **纯黑底**（RGB 0,0,0），没有暗角、没有颗粒。
- **地面不是一条线，而是一段渐变**：从地平线往下由 0 渐变到灰 16～30（屏幕最底部）。地平线随镜头缩放和平移移动，远景时地平线更高、渐变更长。这条渐变就是全片唯一的"空间感"。
- 编程集更极端：大部分时间连地面渐变都没有，就是一片黑，空间完全靠角色站的位置暗示。

### 1.2 颜色

| 用途 | 颜色 | 备注 |
|---|---|---|
| 橙色火柴人（数学 / 几何 / 物理） | `#FF6E00`（255,110,0） | 纯色，不描边、无阴影 |
| 黄色火柴人（编程） | `#FEC400`（254,196,0） | 纯色 |
| 白色算式 / 线条 | `#FFFFFF` | 纯白 |
| 笔记本 | 机身 `#CACACA`、边缘 `#979797`、屏幕背面一个小 logo | 画得很简化 |
| 编程集代码配色 | VS Code Dark+ | 见 1.4 |
| 几何集的"发光" | 金黄 `#FFC830` 到白的渐变 | 高能量的时候整屏被染成金色 |

**全片只有"黑底 + 白色世界 + 一个高饱和角色色"**，任何时候画面里的颜色都不超过 3 种（发光时例外）。这是它干净、一眼能看懂的根本原因。

### 1.3 火柴人的造型（以站立高度 H 为单位）

| 部位 | 比例 |
|---|---|
| 头直径 | 0.23 H（很大的头） |
| 线条粗细 | 0.052 H（站在画面中间、高 540px 时约 28px） |
| 颈到胯（躯干） | 0.32 H |
| 腿（胯到脚） | 0.45 H，大腿 ≈ 小腿 |
| 手臂（肩到手） | 约 0.40 H，上臂 ≈ 前臂 |

- **头**：橙色角色是**空心圆环**（环宽 = 线宽），黄色角色是**实心圆**。
- **线头是圆的**（round cap），关节处圆滑连接（round join）。
- **线是手绘感的矢量**：粗细基本均匀，关节处略圆，有时末端稍细，但没有毛边。
- 没有手掌、没有脚掌，四肢末端就是圆头。肩膀在脖子下方一点，两只手臂从同一点出发。
- **镜头近的时候线条一起变粗**：线宽跟着角色大小缩放，不是固定像素。

### 1.4 编程集的代码排版
- 字体：**Consolas** 风格的等宽字（开源替代：Inconsolata，字形非常接近）。
- 配色（实测）：

  | 元素 | 颜色 |
  |---|---|
  | 函数名 `print` `len` | `#D9D8B2`（Dark+ 的 #DCDCAA） |
  | 变量 `a` `b` | `#A0D3F5`（#9CDCFE） |
  | 字符串 `"string"` | `#CB9680`（#CE9178） |
  | 数字 | `#C7D0BE`（#B5CEA8，偏淡） |
  | 括号 `()` `[]` | `#F9C408`（金色，括号配对色） |
  | `=` `+` 等符号 | 白 / 浅灰 |
  | 光标 | 白色**下划线** `_`，闪烁 |
  | 选中 / 运行高亮 | `#333333` 深灰块（选中单个字符时） |
  | 报错 | 出错那段文字底下铺**暗红块**，下方跟一行很小的红色 `NameError` / `TypeError` / `SyntaxError` |

- 代码是**悬浮在空中的大字**（字高约 60～90px），不是编辑器窗口。
- **"运行"的视觉信号**：整块代码被一个**半透明浅灰矩形**盖住一下（像全选），文字颜色变暗，然后结果出现。
- **输出结果是实物**：`print("hi")` 打出来的 `hi` 是一个会掉到地上、能被踢走、能被捡起来的小白字。后面 `BARK`、`BOOM` 这些词会成群飞出来砸人。
- 后期升级成"道具"：`import turtle` 画出越来越粗的白色折线把人追着跑；matplotlib 的**蓝色柱状图**（`#1F77B4`）变成平台；橙色 `cos` 曲线（`#FF7F0E`）变成地形；pygame 窗口的 `—  ☐  ✕` 标题栏变成场景边框。

### 1.5 数学集的排版
- 白色**人文无衬线体**（类似 Segoe UI / Open Sans），数字比例偏圆。
- 算式就是场景本身：`1+1=2`，角色把 `1` 举起来、把 `+` 当武器、把 `=` 当跳板。
- 后段出现：数轴、单位圆（细白线 + 浅灰网格）、正弦曲线展开、3D 螺旋面（白色线框 + 半透明灰面）。

## 2. 镜头语言

- **几乎是一镜到底。** 编程集 8 分钟只检测到 40 次大的画面突变，大部分还是爆炸闪白；数学集 14 分钟更少。转场主要靠**虚拟摄像机**：推、拉、平移、跟随角色。
- **镜头是 2D 摄像机**：整个世界一起缩放和平移，地面渐变跟着动。没有透视（3D 线框物体除外）。
- **推近 = 情绪**：角色发现新东西、生气、思考时镜头慢慢推近，人物占满半屏。
- **拉远 = 规模**：算式变长、柱状图变高、`1111…` 排成方阵的时候，镜头大幅拉远，角色缩成一个点。
- **轻微漂移**：静止对话段，镜头也会以几个像素的幅度缓慢漂移（`b104` 那组连拍里能看到整排算式在慢慢平移）。
- **震屏只给冲击**：撞击、爆炸那一下，持续 3～6 帧，幅度 10～30px，随后快速衰减。不会跟着音乐一直震。

## 3. 动作语言（最难、也最重要）

- **24 帧原生**（实测平均帧率 23.98 / 30），但几乎每帧都有中间画，动作很顺。
- **夸张的预备和缓冲**：起跳前先蹲，出拳前手往后拉，落地后膝盖压下去再弹起。动作曲线是"慢—快—慢"，打击那一瞬间是 1～2 帧的极快位移。
- **拖影帧（smear）**：快速挥动时手臂被拉长成一条弧，或者画出 2～3 个残影；极快的移动直接是一道白色 / 角色色的速度线。
- **表演靠全身姿态**，没有脸：
  - 挠头（手放头上）、托腮（手抵下巴）、双手抱头 = 困惑
  - 蹲下抱膝 = 沮丧
  - 抬头前倾 = 好奇
  - 后仰摔倒 = 惊吓
  - 甩手、踢东西 = 生气
- **和物体的物理互动**：物体有重量。`hi` 掉下来会弹一下；被踢飞会旋转、拖着弧线落地；笔记本被扔出去会翻滚。

## 4. 特效清单（按出现频率）

| # | 效果 | 在哪集 | 怎么用代码做 |
|---|---|---|---|
| 1 | **逐字打字 + 光标闪烁** | 编程 | 按时间截取字符串；光标 0.5 秒周期闪；每个字配一声键盘音 |
| 2 | **运行闪烁（灰色全选块）** | 编程 | 半透明矩形 + 文字降亮度，持续约 0.3 秒 |
| 3 | **报错暗红块 + 小红字** | 编程 | 文字背景铺暗红；小字从下面淡入 |
| 4 | **文字变实物**（掉落、弹跳、被踢飞、旋转） | 编程 / 数学 | 每个字符一个刚体：抛物线 + 落地衰减反弹 + 旋转（解析解，可以逐帧确定性计算） |
| 5 | **文字群爆**（`BOOM` `BARK` 一圈圈往外飞） | 编程 | 粒子系统，每个粒子是一个单词，径向速度 + 自旋 + 透视缩放 |
| 6 | **暖色径向辉光**（爆炸中心的橙棕色大光团） | 编程 / 几何 | 径向渐变 + 叠加混合（lighter），亮度随时间先冲高后衰减 |
| 7 | **闪白 / 整屏过曝** | 几何 / 编程 nuke 段 | 白色全屏叠加 1～3 帧，再按指数衰减；同时把亮部扩散（bloom） |
| 8 | **放射速度线** | 几何 | 从中心向外的细白线，长度和透明度随机，每帧重新生成（漫画集中线） |
| 9 | **能量光束** | 几何 / 数学 | 白芯 + 金色外晕的粗线，多层描边叠加；两端有光斑 |
| 10 | **镜头光晕**（十字星芒） | 编程 nuke 段 | 中心亮点 + 横竖两条长光条 + 柔光圈 |
| 11 | **冲击波环** | 几何 / 编程 | 扩张的圆环，粗细和透明度随半径衰减 |
| 12 | **闪电** | 几何 | 递归中点位移的折线 + 发光描边，每 2～3 帧换一次形状 |
| 13 | **拖影 / 速度线** | 全部 | 角色或物体身后画几条半透明的残影 / 平行细线 |
| 14 | **震屏** | 全部 | 摄像机偏移，衰减的随机噪声 |
| 15 | **turtle 画线**（越来越粗的白色折线追人） | 编程 | 折线按时间延伸，线宽随 `pensize` 变化 |
| 16 | **matplotlib 图表当场景**（蓝柱、茎叶图、正弦曲线） | 编程 | 直接按 matplotlib 默认配色和样式画 |
| 17 | **3D 线框多面体 / 螺旋面** | 几何 / 数学 | 3D 点旋转 + 透视投影 + 发光线段 |
| 18 | **地面灰尘云** | 几何 | 地面上一串柔和的白色团块，往两边扩散 |
| 19 | **数字 / 字符流**（一大串数字像洪水一样冲过来） | 编程 / 数学 | 大量字符粒子沿一个方向流动，带运动模糊 |

**节制原则**：大部分时间画面上只有角色 + 几个白字，特效只在冲突的高潮爆发，爆完马上回到黑底。这种强对比是它"爽"的来源。

## 5. 声音

用频谱和起音检测看了四集（我听不到声音，下面是从波形和频谱读出来的，建议你戴耳机核对一下）：

| 集 | 每分钟起音数 | 谐波能量占比 | 静音段 | 读出来的结构 |
|---|---|---|---|---|
| 编程 | 156 | 0.53（最低） | 51 段，共 38 秒 | **前 100 秒几乎全是音效**：键盘声、短促的"啵"、物体落地，句子之间是真正的静音；约 99 秒（剧情开始打斗）配乐才进来 |
| 数学 | 132 | 0.71 | 2 段 | 一开头就有**持续的音乐垫底**（稳定的低频和中频音高，速度约 117 BPM），音效叠在上面 |
| 几何 | 126 | 0.71 | 4 段 | 同上，高潮段响度明显升高（-16 dB 左右） |
| 物理 | 54 | 0.84（最高） | 1 段 | 以配乐为主，音效少 |

规律：
1. **每个动作都有一个音效**，严格对齐画面：打字 = 键盘音，运行 = 短促的确认音，报错 = 低沉的"嘟"，东西掉地 = 轻响 + 回弹，踢 = 闷响，爆炸 = 低频轰鸣 + 碎片。
2. **安静本身是设计**：编程集开头用静音制造"一个人对着电脑"的孤独感，配乐进来时对应剧情升级。
3. **配乐跟着剧情强度走**，不是从头到尾一个音量；高潮处配乐和音效一起推高。

## 6. 我们怎么复刻

**技术路线**（沿用仓库已有的渲染架构）：Node.js + skia-canvas 逐帧画 → ffmpeg 编码；Python 合成音效。

| 模块 | 作用 |
|---|---|
| `render/src/rig.js` | 火柴人骨骼：头、颈、胯、两只手臂、两条腿（两段式，带肘和膝）；姿势库 + 关键帧插值 + 走路 / 跑步循环 + 拖影 |
| `render/src/cam.js` | 2D 摄像机：推拉摇移、跟随、震屏；地面渐变 |
| `render/src/code.js` | 编程集风格的代码：逐字打字、光标、Dark+ 配色、运行闪烁、报错 |
| `render/src/fx.js` | 后期：泛光、闪白 |
| `render/src/vfx.js` | 特效：辉光、速度线、冲击波、文字群爆、镜头光晕、闪电、残影 |
| `render/src/phys.js` | 确定性的简易物理：抛物线、落地反弹、旋转 |
| `render/src/cues.js` | 音效时间表：画面代码里登记"第几秒发生了什么"，导出给音效合成器 |
| `audio/sfx.py` | 按时间表合成全部音效，混成一条音轨 |

**第一阶段（这次）**：1:1 模仿编程集开头的段落，加上一段特效集锦（文字群爆、辉光、速度线、闪白、turtle 追逐），目标是把**火柴人动作 + 代码交互 + 爆炸特效 + 音效同步**这四件事做到位。角色和剧情的创新留到后面再聊。
