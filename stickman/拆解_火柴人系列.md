素材：`claude专用` 分支 `reference-videos/火柴人系列/` 的 4 集。

| 火柴人 VS 数学（Math） | 14:02 | 橙色空心头（TSC） | 白色算式、数轴、单位圆、复平面 | ★★★★★ 纯矢量 + 白字 + 少量发光 |

| 火柴人 VS 物理（Physics） | 16:08 | 橙色 + 戴牛仔帽的白描边角色 | 星空、太阳、黑洞吸积盘（大量照片 / 渲染素材） | ★★ 背景依赖写实素材，不优先 |

## 1. 画面规格

### 1.1 底色与"地面"
- **纯黑底**（RGB 0,0,0），没有暗角、没有颗粒。
- **地面不是一条线，而是一段渐变**：从地平线往下由 0 渐变到灰 16～30（屏幕最底部）。地平线随镜头缩放和平移移动，远景时地平线更高、渐变更长。这条渐变就是全片唯一的"空间感"。
- 编程集更极端：大部分时间连地面渐变都没有，就是一片黑，空间完全靠角色站的位置暗示。

### 1.2 颜色

| 用途 | 颜色 | 备注 |
|---|---|---|
| 橙色火柴人（数学 / 几何 / 物理） | `#FF6E00`（255,110,0） | 纯色，不描边、无阴影 |
| 黄色火柴人（编程） | `#FEC400`（254,196,0） | 纯色 |
| 白色算式 / 线条 | `#FFFFFF` | 纯白 |
| 笔记本 | 机身 `#CACACA`、边缘 `#979797`、屏幕背面一个小 logo | 画得很简化 |
| 编程集代码配色 | VS Code Dark+ | 见 1.4 |
| 几何集的"发光" | 金黄 `#FFC830` 到白的渐变 | 高能量的时候整屏被染成金色 |

**全片只有"黑底 + 白色世界 + 一个高饱和角色色"**，任何时候画面里的颜色都不超过 3 种（发光时例外）。这是它干净、一眼能看懂的根本原因。

### 1.3 火柴人的造型（以站立高度 H 为单位）

| 部位 | 比例 |
|---|---|
| 头直径 | 0.23 H（很大的头） |
| 线条粗细 | 0.052 H（站在画面中间、高 540px 时约 28px） |
| 颈到胯（躯干） | 0.32 H |
| 腿（胯到脚） | 0.45 H，大腿 ≈ 小腿 |
| 手臂（肩到手） | 约 0.40 H，上臂 ≈ 前臂 |

- **头**：橙色角色是**空心圆环**（环宽 = 线宽），黄色角色是**实心圆**。
- **线头是圆的**（round cap），关节处圆滑连接（round join）。
- **线是手绘感的矢量**：粗细基本均匀，关节处略圆，有时末端稍细，但没有毛边。
- 没有手掌、没有脚掌，四肢末端就是圆头。肩膀在脖子下方一点，两只手臂从同一点出发。
- **镜头近的时候线条一起变粗**：线宽跟着角色大小缩放，不是固定像素。

### 1.4 编程集的代码排版
- 字体：**Consolas** 风格的等宽字（开源替代：Inconsolata，字形非常接近）。
- 配色（实测）：

  | 元素 | 颜色 |
  |---|---|
  | 函数名 `print` `len` | `#D9D8B2`（Dark+ 的 #DCDCAA） |
  | 变量 `a` `b` | `#A0D3F5`（#9CDCFE） |
  | 字符串 `"string"` | `#CB9680`（#CE9178） |
  | 数字 | `#C7D0BE`（#B5CEA8，偏淡） |
  | 括号 `()` `[]` | `#F9C408`（金色，括号配对色） |
  | `=` `+` 等符号 | 白 / 浅灰 |
  | 光标 | 白色**下划线** `_`，闪烁 |
  | 选中 / 运行高亮 | `#333333` 深灰块（选中单个字符时） |
  | 报错 | 出错那段文字底下铺**暗红块**，下方跟一行很小的红色 `NameError` / `TypeError` / `SyntaxError` |

- 代码是**悬浮在空中的大字**（字高约 60～90px），不是编辑器窗口。
- **"运行"的视觉信号**：整块代码被一个**半透明浅灰矩形**盖住一下（像全选），文字颜色变暗，然后结果出现。
- **输出结果是实物**：`print("hi")` 打出来的 `hi` 是一个会掉到地上、能被踢走、能被捡起来的小白字。后面 `BARK`、`BOOM` 这些词会成群飞出来砸人。
- 后期升级成"道具"：`import turtle` 画出越来越粗的白色折线把人追着跑；matplotlib 的**蓝色柱状图**（`#1F77B4`）变成平台；橙色 `cos` 曲线（`#FF7F0E`）变成地形；pygame 窗口的 `—  ☐  ✕` 标题栏变成场景边框。

### 1.5 数学集的排版
- 白色**人文无衬线体**（类似 Segoe UI / Open Sans），数字比例偏圆。
- 算式就是场景本身：`1+1=2`，角色把 `1` 举起来、把 `+` 当武器、把 `=` 当跳板。
- 后段出现：数轴、单位圆（细白线 + 浅灰网格）、正弦曲线展开、3D 螺旋面（白色线框 + 半透明灰面）。

## 2. 镜头语言

- **几乎是一镜到底。** 编程集 8 分钟只检测到 40 次大的画面突变，大部分还是爆炸闪白；数学集 14 分钟更少。转场主要靠**虚拟摄像机**：推、拉、平移、跟随角色。
- **镜头是 2D 摄像机**：整个世界一起缩放和平移，地面渐变跟着动。没有透视（3D 线框物体除外）。
- **推近 = 情绪**：角色发现新东西、生气、思考时镜头慢慢推近，人物占满半屏。
- **拉远 = 规模**：算式变长、柱状图变高、`1111…` 排成方阵的时候，镜头大幅拉远，角色缩成一个点。
- **轻微漂移**：静止对话段，镜头也会以几个像素的幅度缓慢漂移（`b104` 那组连拍里能看到整排算式在慢慢平移）。
- **震屏只给冲击**：撞击、爆炸那一下，持续 3～6 帧，幅度 10～30px，随后快速衰减。不会跟着音乐一直震。

### 2.1 景别和推拉的实测（编程集，按主角在画面里的高度统计，每秒 10 帧）

| 景别 | 主角高度占画面 | 占全片时间 |
|---|---|---|
| 大远景 | < 12% | 20% |
| 远景 | 12–25% | 33% |
| 全景 | 25–45% | 25% |
| 中景 / 近景 | > 45% | 22% |

- **开头和结尾近、中段远**：前 110 秒（学写代码）主角大多占 33–60%；中段动作戏（turtle 追逐、枪、游戏）大多只占 10–20%；结尾又推回 50–60%。
- **在节拍上推拉，节拍之间稳住**：动作戏里景别每 2–4 秒变一次，每次推或拉约 1–1.5 秒、幅度 2–4 倍（比如 7% → 23%）；推拉之间基本不动。
- **推拉跟着"这一刻要看什么"**：线、图形、爆炸这种占地方的东西出现 → 拉远看全；主角的反应（吓到、疼、得意）→ 推近到 40–90%，看完马上拉回去。
- **大事件先远后近**：核弹那段先是大远景交代规模，紧接着推到主角的近景（占 92%）看反应，再拉回远景。
- **跟拍留空间**：跑动时人物不在正中，身后有威胁时把画面留给身后（人在一侧），往前看的时候留给前方。
- **turtle 追逐 45 秒没有一秒是重复的**：线的形状一直在变（直线 → 折角 → 越来越密越来越粗的之字形），主角的应对也一直在变（跑、躲、跳、被扫中、边跑边捡电脑），中间还靠改代码升级（`speed('fast')` → `pensize(10)` → `speed('fastest')`），最后用 `turtle.bye()` 收尾，主角累倒。

### 2.2 数学集的镜头节奏（前 3 分 20 秒，按主角高度每 2 秒取中位数）

```
0:00   2%  ← 大远景：灰色空间里一个小点，什么都没有（4 秒）
0:04  27%  ← "1" 出现，推到全景
0:08  41%  ← 全景稳住，1=1、1+1=2 …（20 秒不动）
0:30  24%  ← 算式变长 → 拉一次远景（4 秒）
0:36  41%  ← 推回全景
0:54  29%  ← 又拉远（100、减法）
1:12   8%  ← 一长串数字铺满 → 大远景一下
1:14  45%  ← 推回
1:42  64%  ← 对手（-1 = e^iπ）出现 → 近景看主角的反应
1:52  ~7%  ← 对手发威 → 一路拉到大远景看规模
2:04  38%  ← 回到全景继续
2:50   3%  ← 又一个大事件，大远景
```

规律（和编程集一致，更清楚）：
1. **基准是全景（主角占 ~40%）**，人和他手里的东西都看得清。不是一直推推拉拉。
2. **"呼吸"**：每 20–30 秒，内容一变大（算式变长、东西变多）就拉到远景（~25%）几秒，然后推回。
3. **大远景是标点符号**：只在三种时刻用——开场（世界是空的）、规模突然变大（一长串数字、对手变巨大）、高潮前。每次只停 2–6 秒。
4. **近景只给反应**：对手第一次出现时推到 60%+ 看主角吓到，看完马上拉开看对手。
5. **开场一定空**：先让观众看到"什么都没有"，主角是画面里唯一的东西；第一个知识出现时才推近。这个"空"是后面所有东西的对比。

几何集也一样：开场黑底中间一个点（0:15），点 → 线 → 主角在线上走 → 角 → 三角形 → 多边形 → 圆 → 立体，镜头随着图形变大一步步拉远。

## 3. 动作语言（最难、也最重要）

- **24 帧原生**（实测平均帧率 23.98 / 30），但几乎每帧都有中间画，动作很顺。
- **夸张的预备和缓冲**：起跳前先蹲，出拳前手往后拉，落地后膝盖压下去再弹起。动作曲线是"慢—快—慢"，打击那一瞬间是 1～2 帧的极快位移。
- **拖影帧（smear）**：快速挥动时手臂被拉长成一条弧，或者画出 2～3 个残影；极快的移动直接是一道白色 / 角色色的速度线。
- **表演靠全身姿态**，没有脸：
  - 挠头（手放头上）、托腮（手抵下巴）、双手抱头 = 困惑
  - 蹲下抱膝 = 沮丧
  - 抬头前倾 = 好奇
  - 后仰摔倒 = 惊吓
  - 甩手、踢东西 = 生气
- **跑步**（`analysis/ref_pose.py` 从编程集 3:23 的近景逐帧提取骨架，30 帧/秒）：
  - 每步 5 帧（约 0.17 秒），4 张姿势循环：**蹬地**（后脚在胯后下方、后腿伸直，前腿提膝，这张停 2 帧）→ **腾空劈腿**（后脚踢到身后膝盖高、前脚伸到前方 0.35H）→ **前脚落地** → **两腿在身下交错**
  - **上身是往后仰的**：平均约 -10°，腾空那一帧到 -28°；头在胯后方约 0.1H。往前倾着跑反而不像
  - 胯很高（腿几乎伸直），腾空时再往上冲
  - 手肘弯成直角贴着身体：前拳举到下巴高度，后手垂在胯后
  - 我们的实现直接用这组数据（按腿长缩放），见 `render/src/moves.js` 的 `run`；`render/src/tools/move_frames.js` 可以把任意动作按原片近景的大小渲染出来，用同一个脚本量化对比
- **和物体的物理互动**：物体有重量。`hi` 掉下来会弹一下；被踢飞会旋转、拖着弧线落地；笔记本被扔出去会翻滚。

### 3.1 探索的逻辑和内心过程（编程集开头 0:08–1:10 逐段看）

原片的主角不是在"演示代码"，而是在**一步步弄明白一个陌生的东西**。每一步都是很小的试探，结果决定下一步：

| 原片时间 | 发生了什么 | 角色的内心 → 动作 |
|---|---|---|
| 0:08–0:13 | 醒来，看见半空中一个光标 | 注意到（头转过去、停住）→ 好奇（托腮 1–2 秒、歪头）→ **犹豫着慢慢伸手** → 碰一下 → 手缩回来 → 转开 |
| 0:13–0:17 | 发现电脑，按键，字出现在光标那里 | 试探着按 → 抬头看结果 → 明白"按键 = 出字" → 敲出 hello |
| 0:18–0:23 | 运行 hello → 报错变红 | 吓一跳、电脑脱手 → **赌气走开** → 又不情愿地回来，跪下垂着头 → 慢慢删掉 |
| 0:28–0:33 | `print()` 运行没反应 | **连按好几次**（越按越快）→ 挠头 → 想 → 把光标挪进括号里加字 |
| 0:34–0:42 | `print("hi")` → hi 变成实物掉出来 | 吓得往后退、电脑掉了 → 手护在脸前盯着看 → 慢慢走过去 → 蹲下 → **戳一戳** → 捡起来端详 → 回去再敲一遍验证 |
| 0:45–1:10 | 多行 print、变量、四则运算 | 每次只改一点点（a = 1 → 2 → 9 → 3+2 → 3*2 → 3/2 → 3//2），运行，看结果，有小反应 |

规律：
1. **反应链**：注意到（头先转过去、身子一顿）→ 停住看（0.3–0.7 秒）→ 情绪姿势 → 小心试探 → 得出结论 → 下一步。中间的"停住"不能省，那是在"想"。
2. **好奇**：托腮、歪头、身体前倾、慢慢靠近、伸手前先犹豫。
3. **困惑**：挠头（有声音：几下亮的沙沙声，每下约 0.17 秒，比脚步轻很多）、左右张望、连按几次。
4. **受挫**：走开、垂头、跪着，动作变慢。
5. **明白了**：抬头看结果、点头、马上再试一次验证。
6. **知识从 0 到 1**：每一步只多知道一点点，而且结果是看得见的（字出现、报错变红、hi 掉下来），观众跟着主角一起弄明白。

我们的实现：`render/src/acting.js`（注意到、看、托腮、挠头带声音、吓一跳、试探着戳、反应过来、想到主意、点头），样片 `scene_v4.js`。

### 3.1.1 动作逐帧实测（`analysis/ref_strip.py` 拉动作条，`render/src/tools/move_frames.js` 出我们的同款动作条对比）

**总规律：快动作 + 长停顿。** 原片的姿势变化几乎都在 1–5 帧内完成，然后定住；静止的时候几乎完全不动（不是一直在晃）。我们的弹簧系统天生"软"，做不出 1 帧到位，所以极限姿势要走精确路径（`path`），停顿时把"活"的晃动调小（`noise` 默认已从 1 降到 0.5）。

| 动作 | 原片（编程集，30fps） | 我们原来的问题 | 现在 |
|---|---|---|---|
| 吓一跳（0:34 hi 掉出来） | 第 1 帧直接甩到极限：上身后仰约 35°、头往后甩、双手往上甩，电脑脱手 → 定住约 6 帧（0.2 秒），还在微微往后飘 → 约 5 帧回正，双手护在脸前 → 护着脸愣住 1 秒以上不动 | 后仰只有十几度，弹簧慢慢过去，没有定格 | `startle`：0.04 秒到极限，定 0.22 秒，0.18 秒回正，护脸 hold |
| 被砸 | （同吓一跳的节奏，方向反过来：缩脖子、弯腰） | 只动了头，几乎看不出来 | `bonk`：1 帧缩脖子弯腰沉肩，双手捂头揉两下；`hip:false` 时只缩头弯腰 |
| 走（0:18 赌气走开） | 触地时两脚前后分开约 0.5H，两腿成倒 V（和竖直约 30°），胯 0.42H（站直 0.44H）；两只脚轮流迈，一只在空中时另一只踩稳；触地姿势停得久，两脚交错那一下很快 | 两只脚同时在动 → 小碎步像老头；长距离时整段缓入缓出、弹簧滞后，后半段胯落在脚后面人蹲下去（胯高掉到 0.28H） | `walk`：步幅 0.4H（按腿长换算的同样角度），脚在空中 60% 时间，胯走精确路径（只在首尾一步加减速），触地时胯最低；`arms: true` 摆臂 |
| 醒来起身（0:08） | 坐起 → 收腿 → 站直，共约 0.4 秒；然后站着不动 0.5 秒 | `getUp` 约 1.2 秒，偏慢 | 用 `getUp(t, { speed: 2 })` 加快 |
| 想（0:09） | 一只手托下巴，身体笔直、腿直、几乎不动 1 秒多 | 托腮时重心在晃 | 晃动已调小 |
| 伸手碰（0:10） | 手慢慢伸过去，碰到后停 0.3 秒；缩回来时手蜷在胸前定住 | — | `poke` 基本一致 |
| 被线扫倒（2:42） | 仰面落地后顺着惯性往后滚：腿翻过头顶 → 摇回来坐起、手撑在身后，约 0.6 秒 | 落地就躺平不动 | `launch({ land: 'back', roll: true })` |
| 顶住大力量（2:46 抓住 turtle） | 两脚分得极开（约 0.8H），后腿蹬直、前腿弯，上身前倾约 40° 扛着，脚底在地上滑出灰 | 没有这个动作 | 记下，做到时用 `hip` + `foot` 摆这个姿势，配 `recoil_slide` |
| 赌气 / 泄气（0:20） | 停下 → 头一垂、肩一沉（2–3 帧）→ 很快跪下（0.2 秒）→ 低着头定住 0.6 秒 → 才伸手去键盘 | — | 用"快动作 + 长停顿"组合现有的 `kneel` |

工具用法：
```
python3 stickman/analysis/ref_strip.py 原片.mp4 34.2 35.4 out.png --mode follow   # 原片：以人为中心逐帧裁
```

### 3.2 故事结构：知识阶梯 + 对手

三集都是同一个骨架：

| | 数学 | 几何 | 编程 |
|---|---|---|---|
| 知识阶梯（每一步只多一点） | 1 → 1=1 → 1+1=2 → 长串加法 → 100 → 减法 → 0 → 负数 | 点 → 线 → 角 → 三角形 → 多边形 → 圆 → 立体 | 光标 → 按键出字 → hello 报错 → print → print("hi") → 变量 → 运算 → 字符串 → for → while → 条件 → 列表 → turtle → 图表 → pygame |
| 麻烦 / 对手 | 1:40 自己凑出的 `-1 = e^iπ` 活了，把他打倒 | φ（黄金比）——自己找出来的东西变成追着他的家伙 | 没有固定对手：自己写的 while True、turtle 线、pygame 方块反过来追他 |
| 收尾 | 对手变朋友，The End | 一起变成大立体，The End | turtle.bye()、累倒 |

要点：
1. **麻烦是主角自己造出来的**（自己学会的东西用过头、或者自己拼出的式子活了），不是外面突然来个坏人。这样"学知识"和"打架"是同一件事。
2. **对手出现在知识攒够之后**（数学 1:40、编程 1:50），前面是安静的探索；对手一来，节奏和镜头都变大。
3. **用刚学会的东西对抗**：打架的招式就是知识阶梯的下一级，所以打着打着又学到新东西。

### 3.5 打斗（第 5 轮实测；逐帧原始记录在 `研究/打斗拆解_{数学,编程,几何}.md`）

原片打斗几乎没有拳脚，全是**兵器（+ − 号、尺子、光标）+ 闪躲 + 用知识反制**。按 24 帧计：

**打中那一下**
- 不停帧、不震屏。只有 1 帧放射白光 + 1–2 帧火花 + 结果字形（比如 `0`）在 5 帧内淡出。重击才闪全屏白 1 帧。
- 被打：1 帧接触、2 帧头先甩、约 6 帧慢慢倒下；不是一下子飞走。

**一招的时长**
- 出招 1–2 帧（带 1 帧拖影）；预备 2–5 帧（约出招的 2–3 倍）；收招 5–6 帧。
- 越重的招预备越长，但出招一样快（几何集：轻戳预备 2 帧、终结技后收 4 帧，出手都只有 2 帧）。
- 编程集里代码高亮 4–6 帧就是"预备"：观众先看到要变的那行，再看到攻击。

**节奏**
- 快拍每拍 5–9 帧；连续 3–6 拍之后**一定**停（7–10 帧 / 16–22 帧 / 1 秒以上）。停顿放在两招之间，不放在打中的那一刻。
- 一个回合 3–6 秒。主角出手多，但回合通常以对手的一记反击结束。
- 一串连击里反应逐级加重：后仰 → 踉跄 → 弯腰 → 被打飞。
- 加速：几何集连射间隔 22 → 12 → 12 → 10 → 8 → 6 帧，然后逃。

**被打飞 / 倒地 / 扑**
- 被打飞：先爆发再减速，每帧位移约 0.27, 0.49, 0.48, 0.23, 0.26, 0.12, 0.02 H。
- 倒地：3 帧倒 + 10 帧躺 + 5 帧起。
- 扑：4 帧预备 + 7 帧腾空（2.3 H）→ 扭打 26–38 帧 → 被甩出去。
- 终结技（几何集）：慢慢准备 → 2 帧出手 → 22 帧随势定格 → 38 帧飞行 → 12 帧白屏。

**强弱和"差一点"**
- 差一点比打中多：攻击在主角离开后 2–4 帧才落到原位。主角约 80% 的时间在躲或挨打，赢靠改代码。
- 强弱悬殊时，强的一方几乎不动。
- 攻击物落下后变成地形（可以站、可以躲在后面）。
- 一种武器升级 3–4 次，然后换新武器。

**镜头**
- 一个回合内镜头固定、全景框住两人；只有大位移（被打飞）时 6–12 帧快速拉远；出新武器 / 蓄力时推近。

**我们的实现**：`render/src/fight.js`（招式 = 24 帧关键帧，自动够距离）+ `analysis/fight_moves.json`（33 招，数学 / 编程 / 几何集实测，拳脚类是估的、原片几乎没有）+ `FightFX`（光、火花、字形）+ `exchange`（按"拍"编排攻防），演示在 `SCENE=fight`。

| 类别 | 招式（`fight_moves.json` 里的名字） |
|---|---|
| 架势 / 移动 | guard_weapon、guard、step_in、step_back |
| 兵器攻击（实测） | thrust（刺）、slash（劈）、upswing（上挑）、shoot（射）、throw_big（终结技投掷） |
| 防守 / 闪躲 | parry（兵器相碰）、lean_dodge、duck、block、dodge_back、brace（扛住）、dive（扑出去躲）、tuck_jump（收腿跳过） |
| 受击 | stagger、hurt_fold、hurt_high、hurt_body、knock_back、hit_fall_back（头先甩再后倒）、launched / launch_up（打飞）、knockdown_quick、startle_sit（吓得跳起坐倒） |
| 冲撞 | tackle、lunge_punch |
| 拳脚（估计） | jab、cross、uppercut、front_kick |

## 5. 声音

用频谱和起音检测看了四集（我听不到声音，下面是从波形和频谱读出来的，建议你戴耳机核对一下）：

| 集 | 每分钟起音数 | 谐波能量占比 | 静音段 | 读出来的结构 |
|---|---|---|---|---|
| 编程 | 156 | 0.53（最低） | 51 段，共 38 秒 | **前 100 秒几乎全是音效**：键盘声、短促的"啵"、物体落地，句子之间是真正的静音；约 99 秒（剧情开始打斗）配乐才进来 |
| 数学 | 132 | 0.71 | 2 段 | 一开头就有**持续的音乐垫底**（稳定的低频和中频音高，速度约 117 BPM），音效叠在上面 |
| 几何 | 126 | 0.71 | 4 段 | 同上，高潮段响度明显升高（-16 dB 左右） |
| 物理 | 54 | 0.84（最高） | 1 段 | 以配乐为主，音效少 |

规律：
1. **每个动作都有一个音效**，严格对齐画面。
2. **安静本身是设计**：编程集开头用静音制造"一个人对着电脑"的孤独感，配乐进来时对应剧情升级。
3. **配乐跟着剧情强度走**，不是从头到尾一个音量；高潮处配乐和音效一起推高。
4. **响度**：编程集整体 -17 LUFS，响度范围（LRA）16 LU，开头 100 秒只有 -26 LUFS。安静的地方很安静、爆的地方很响，不是一直顶着音量。数学集 -14.6 LUFS。

### 5.1 编程集的声音词典（逐个事件实测）

方法：`analysis/ref_events.py` 把编程集前 100 秒（纯音效，没有配乐）切成 216 个声音事件，逐个测量峰值、长度、起音、频谱重心、主频，以及每 10 ms 的主频走向。然后把每个事件对应时刻的画面截下来，确认这个声音是什么。

结论：**编程集的界面音是"有音高的提示音"，每一种动作固定一个音高和形状**，不是随便的噪声。

| 声音 | 画面里发生了什么 | 实测 |
|---|---|---|
| 光标闪烁 | "_" 每亮一次、灭一次 | 20–28 ms 的"嘀/嗒"。亮 = 2050 + 1289 Hz，灭 = 2871 + 1792 Hz，交替出现。只在安静段听得到 |
| 键盘 | 每敲一个字 | 130 ms，主峰 2296 Hz，重心 3.4 kHz，另有 87 / 1101 / 1453 / 3738 / 8050 Hz 共振。按下、~20 ms 触底、~60 ms 松开，共三个瞬态 |
| **运行** | 灰色高亮闪一下（代码没有输出） | 235 ms，-12.5 dB，每次几乎一模一样。主频走向（每 10 ms）：回车键 → 585 585 585 585 → 468 445 445 → 562 585。木质的"嘟"，中间往下沉一下 |
| **打印结果出现** | `1`、`2`、`hi` 冒出来 | 全片最响的界面音（-5 dB），153 ms。1250 Hz 的"叮"带 35 Hz 颤音（频谱上每隔 35 Hz 一条边带），40 ms 起叠一个低八度、从 630 Hz 往下滑的"咚" |
| **报错** | 代码变红的那一下 | -5 dB，约 300 ms，分四段：1010→1250 Hz 的音 → 刺耳的亮噪声（重心 4–5 kHz，40 ms 处有个 7.6 kHz 尖点）→ 750 Hz 的音 → 很轻的 5.6 kHz 余音 |
| 碰到代码 / 捡起东西 | 戳光标、捡起 `hi` | "啵～"上滑：60 ms 内 445 → 720 Hz，85 ms 掉到 375 Hz。另一种变体 445 → 632 → 328 Hz（蹲下摸电脑、按回车前） |
| 选中文字 | 白色高亮框 | 40 ms 的 6.2 kHz"嚓" + 2.1 kHz 和 609 Hz 的短尾巴 |
| 脚步 | 走路 | 58 Hz 的超低频闷点（+105 Hz 泛音），45 ms，约每秒 6 步 |
| 身体着地 | 跪下、电脑掉地前后 | 同样的超低频闷点，更响（-12 dB）、更长（60 ms） |
| 电脑落地 | 电脑摔在地上 | 70–140 Hz 闷响 → 40 ms 起一串塑料共振（1054–2039 Hz）+ 4 kHz 的"咔"，107 ms |
| 爆炸 | `print(*bomb)` | 不是一下就没的"砰"，而是一段**持续约 2.6 秒的轰鸣**（RMS 约 -13 dB，宽频，重心约 2.5 kHz），然后随转场切断 |
| turtle 画线 | 白线在屏幕上画 | 明亮的沙沙声，重心约 4.3 kHz，持续好几秒，峰值约 -9 dB |

### 5.2 我们的音效怎么对齐原片

- `audio/sfx.py` 给每一种声音写了一个函数，**按上表的音高、走向、长度合成**，峰值调到原片同类声音的实测值，所以各种声音之间的音量比例和原片一致。
- 原片的声音是录音或处理过的，每个频带都有能量；纯合成音只有几根谱线，中间是深谷。所以先从原片量出每类声音的频谱包络（48 个频带，存在 `audio/ref_spectra.json`，只存数字，不存原片音频），再用整形噪声把合成音缺的频带补上。
- `analysis/compare_sfx.py` 用同一套量法逐类对比原片和合成音。12 类声音的结果：

  | 指标 | 第一版 | 现在 |
  |---|---|---|
  | 平均谱形相似度 | 0.74 | **0.89** |
  | 平均包络相似度 | 0.83 | 0.82 |

  包络相似度基本持平。其中"电脑落地"一类只有 0.38：原片那一处截取窗口里混进了紧跟着的下一个声音，这一项的参照本身不干净。
- 真实录音（键盘、脚步、着地、电脑落地等）用你本地的素材效果会更好：`analysis/pick_samples.py` 扫描你的素材库，按上面的实测指纹给每个文件打分，自动挑最像的放进 `audio/samples/`。
