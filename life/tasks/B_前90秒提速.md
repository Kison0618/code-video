# 任务 B：把《生命之美》前一分半的节奏压快（时间映射）

## 项目
`F:\AI\For AI to use\codex2\视频\work_outputs\code-video-upload\life`（git 仓库，分支 claude/code-video-production-kotvwd）。先读 `README.md`、`build.js`、`render/src/timeline.js`、`render/src/render.js`、`render/src/render_all.js`、`render/src/preview.js`、`audio/synth.py`。

所有画面和声音都是"源时间 t"的函数，写死了大量绝对时间。**不要去改各场景里的时间常数**。做法是加一层时间映射：成片时间 T ↔ 源时间 t。

## 映射表（源时间 → 成片时间，分段线性）
| 源 t | 成片 T |
|---|---|
| 0 | 0 |
| 3 | 2.2 |
| 23.5 | 18.6 |
| 34 | 26.0 |
| 97 | 73.25 |
| 之后 | T = t − 23.75（速率 1，不变） |
即：冷开场 3–23.5 速率 0.8；片名 23.5–34 速率约 0.705；第一幕 34–97 速率 0.75。
成片总时长 = 353 − 23.75 = 329.25 秒。

## 要做的事
1. 在 `render/src/timeline.js` 里定义映射表 `WARP`（上表），导出 `toSrc(T)`、`toOut(t)`、`OUT_DURATION`；JSON 导出（`require.main === module` 分支）里也带上 `WARP` 和 `OUT_DURATION`。源数据（SUBS、HITS 等）保持源时间不变。
2. 画面：`render.js`、`render_all.js`、`preview.js` 里，帧号/时间按**成片时间**计；调用 `renderFrame(ctx, toSrc(T), frame)`。`render_all.js` 默认结束时间改成 `OUT_DURATION`。`preview.js` 的参数仍是**源时间**（便于对照分镜），不要改它的含义，但在 README 写清。`--from/--to` 的含义改为成片时间，`build.js` 里写死的 `'353'` 改成从 timeline 读 OUT_DURATION。
3. 声音：`audio/synth.py` 里实现同样的 `to_out(t)`（读 JSON 里的 WARP）。
   - 所有 `place(buf, t, ...)` 的放置时间都映射：最简单是在 `place()` 内部做 `t = to_out(t)`。
   - 和弦段 SECTIONS：起点映射，时长 = `to_out(a+d) − to_out(a)`。
   - 琶音 ARP_RANGES：在**成片时间**上按原 step 间隔生成音符（不要让琶音被压密到更快），用 `chord_at(to_src(T))` 查和弦。注意 place() 已经映射，这里要避免二次映射（可以给 place 加 `out_time=True` 参数）。
   - 心跳：映射后的心跳会变快一点，这是想要的效果，保留。
   - 末尾淡出（350.4–352.8）、N 的长度、最终裁剪长度改为成片时长。
4. 字幕在源时间里绘制，映射后显示时长会缩短。写个小检查：列出所有 SUBS 映射后的显示时长，任何一句 < 2.8 秒就在结果里报告（不要自行改文案）。
5. 验证（必须实际跑）：
   - `PYTHON=F:/AAA/python.exe node build.js --version v2-warp`（整片构建，带 NVENC 约 6 分钟）。
   - ffprobe 确认成片时长 ≈ 329.25s、60fps、音画时长一致。
   - 用 ffmpeg 从成片抽帧：成片时间 2, 15, 22, 40, 60, 74, 100, 200, 300, 325 秒，拼成一张对照图 `render/out/v2_warp_sheet.png`（每格标时间）。
   - 用 ebur128 报告整片响度和真峰值。
   - 抽查对齐：成片 T = toOut(23.5) 与 toOut(57.0) 两个重击点附近 ±0.5 秒的音频峰值时刻，与画面闪光是否对齐（报告数值即可）。
