# 人类误判心理学 · 云端协作交接（先读这份）

你是云端 Claude，负责这个系列视频的**大部分制作工作**。配音、1080p 成片、混音这三步由用户本地的 Claude 收尾，你这边只用低清预览自查，不出成片。

## 0. 系列是什么
- 芒格《人类误判心理学》的科普短视频系列，每集讲一种误判倾向。
- 发布在抖音和 B 站，账号主要做芒格相关内容。
- 第一集已交付，讲的是总论：蚂蚁的固定程序，加上绿松石“贵就是好”的故事，3 分 24 秒。
- 第二集已定选题：**权威误导倾向**。见 `ep02/选题定稿.md`，调查原文在 `ep02/research/`。

## 1. 分工与顺序（不要跳步）
1. **文案（你）**：先和用户聊文案。用户定稿后，写成 `ep02/voice/lines.json`，格式照抄 `ep01/voice/lines.json`。
2. **配音（本地）**：用户本地会用 Fish Audio 配音、对齐时间轴，然后把 `ep02/voice/lines_timed.json` 推回仓库。配音前不要做画面，因为画面是按配音时间卡点的。
3. **画面（你，最大的一块）**：分镜，带参考图生成素材，写场景代码，渲染低清预览和拼图自查，推到仓库。
4. **收尾（本地）**：1080p 渲染、混音（BGM 和音效）、语音识别核对同步、封面、发布文案。

每完成一个阶段，在 `ep02/HANDOFF.md` 里写清楚三件事：做了什么、文件在哪、有哪些没把握的地方。

## 3. 用户反复强调过的规则（每条都踩过坑）
**文案**
- 开头 0–2 秒直接给出强观点，并且和观众有关，带“你”。不用比喻铺垫，不讲故事开场。
- 句与句之间要有因果，一句接一句。强观点 → 解释 → 案例。
- 角色台词用第一人称口语，旁白和角色之间要有过渡句。
- 主旁白语速约 5.6 字/秒，一集控制在 3–4 分钟。章节编号只出现在画面里，不念出来。
- 事实要准：只用 `ep02/research/` 里有出处的事实。哪些边界不能越过（比如金额不写、小张是研究生），见选题定稿。

**画面**
- **画面只画当前这句话。** 每句至少有一次画面变化。屏幕上的文字只用旁白里的关键词。
- **要具体，不要抽象**：用具体的物件、场景和人，不用需要观众解码的比喻。单个主体可以连续承载好几句。
- **每个概念换一种视觉装置**，可以混用插画、拟真界面、实物隐喻、动态文字。全片只用一个母题会被评为单调。
- **按手机可读来设计**：字幕 ≥ 60px，标签 ≥ 30px，线宽 ≥ 2.5px。把画面缩到 900px 宽检查一遍。
- **动作少而慢，不抢字幕。** 文案第一，画面辅助。
- **禁止**：皮克斯式 CG、糖果色高饱和、满屏高光、大眼萌；火柴人或几何图元线稿；海报或 PPT 式排版；只换配色的“新风格”。

**素材生成**
- 素材一律**带参考图生成**，不靠纯文字提示，也不用代码从零硬画。代码只负责排版、动效和合成。
- 真人一律用**有授权的照片**作参考（例如 Wikimedia Commons 的 CC 图），记下作者和许可证，写进 `ep02/素材来源.md`。第一集里芒格就是因为纯文字生图画成了大胡子才返工。
- 生成之后**打开看图**再用，不要只看文件名。图里不要带文字，文字由代码排版。
- 提示词写短：参考图 + 风格 + 主体，不要写长篇模板。

**封面**：钩子带“你”、戳痛点、字要大。参考 `ep01/render/out/封面_3x4.jpg`。标题格式：`vibe知识大赏｜<钩子> #话题`。

## 4. 技术注意
- `src/core.js` 里的 ffmpeg 路径和字体路径是用户 Windows 机器上的。云端请用环境变量覆盖（见 core.js 开头的说明），不要改动 Windows 上的默认值。
- 没有 `lines_timed.json` 时，可以按“字数 ÷ 5.6”估一份同格式的文件，命名为 `lines_timed_est.json`，只用来预览。真时间轴推上来后，画面会自动跟着变，因为场景代码只用 `TL.L(id)` 和 `TL.at(id,'词')` 取时间，不写死秒数。
- 编码参数必须保留 `-x264-params b-pyramid=none:keyint=60:min-keyint=30`。第一集因为默认的 b-pyramid，播放器丢 B 帧时出现了大面积方块花屏和字幕回退。
- 预览用 `node src/preview.js out/_x.png <时刻...>` 抽帧拼图。云端只渲染 720p 或片段，不出整片成片。
- 不要提交大文件：配音、mp4、wav 都不进仓库。单张图片控制在 10 MB 以内。

## 5. 和用户沟通
- 用户说“不好看”，通常意味着缺少和内容相关的视觉母题，不是让你调颜色。
- 给方案时，要给真正不同的方向，不要同一个思路换皮。用户不满意时，先判断问题出在文案、结构还是画面，不要继续生成同类变体。
- 说实话：没做到的、没把握的，直接写出来。
