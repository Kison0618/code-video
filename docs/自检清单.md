# 自检清单（每一轮交付前，逐条过一遍；不过关自己改，改完再交）

> 这份清单收录：你说过的所有要求 + 我犯过的错。以后每支片、每一轮都用它自查。
> 新的要求、新的错，当轮就补进来（写清是哪支片、哪一版）。

---

## A. 交付与流程

- [ ] **不渲染成片，也不讲怎么渲染。** 只交工程、文案、设计说明和自查用的关键帧（`关键帧/`、`封面/`）。
- [ ] **不在回复里提 token / 撤销令牌这类提醒。**
- [ ] 推到仓库 `KisanQi/video-library` 的 **`Lusion` 分支**；只提交相关文件（不提交 `node_modules/`、`package-lock.json`）；做到一半也要推 WIP。
- [ ] 推完分别核对 `git rev-parse HEAD` 和 `git rev-parse origin/Lusion` 一致。
- [ ] 横屏 1920×1080 和**竖屏 1080×1920** 两版都要有；竖屏是重新构图，不是从横屏裁。
- [ ] 回复用中文，先说结果，简短；说实话：做不到、没验证的，直接写出来。

## B. 内容与文案（见 `docs/文案手册_v1.md`）

- [ ] 以用户给的材料为核心，挑**有冲击力**的观点；一支片只讲一个痛点 / 一个知识核。
- [ ] **事实必须对得上来源**：案例、页码、章节、年份逐条核对（来源写进 `文案.md` 的“来源”列）；材料里没有的，标成“本片的比喻”。
- [ ] **不说满**：没有把握的结论用“可能 / 多半 / 也许”；不夸大研究结论，不把相关说成因果。
- [ ] **开头前几句必须亮观点**：第一句就说清父母是什么样的（可以带一点指责），接着点出后果，再让观众在自己身上认出来（委屈、愧疚）；为什么会这样，留给后面的科普。不能只讲一个故事、没有观点。
- [ ] 开头 0–17 秒不出现术语，观点用一个具体的人、具体的场景落地。
- [ ] **结尾回答开头、回到开头那一幕**（开头的人必须在结尾再出现）。
- [ ] 结尾不堆重复的口号；最后一句只说一次，不在正片后面再加“彩蛋式”重复。
- [ ] 字幕（含大字）每分钟 ≤ 17 行，每行 ≤ 18 个字；至少 3 段 ≥ 4 秒的留白；至少 2 组对仗；只用一次“不是……而是……”式的反转。
- [ ] **片尾卡只放片名**；参考文献写进 `文案.md`，发布时放进简介，不放进画面。
- [ ] **例子要让观众一眼站在孩子这边**：用“明显该被安慰”的事（摔倒、受伤、害怕、难过），不用碰坏东西、闯祸这类观众可能觉得“该罚”的例子；就算原书案例是这样，也可以改成本片的场景，在来源列写清改了什么。
- [ ] **说法要贴近中文家庭的日常**：不写“孩子去哄父母”这种不常见的说法，换成“找你倒苦水”“没人听你说”这类一听就懂的。
- [ ] **抽象的话先说行为、再说后果**（“他们摔门、摆脸色，难受的却是你”），不要只说“他们让你难受”。
- [ ] **结尾的“他 / 你”一眼看得懂是谁**：画面里长大的你不能从父亲的门里走出来、也不能和父亲同一个样子；最好一句回应开头一句。

## C. 画面与特效（见 `docs/画面手册_v1.md`、`docs/结构手册_v1.md`）

- [ ] **代码特效要华丽**：学参考片（熵 / 37% / 运气的形状 / 惊奇之学）——形状由光点组成；同一批光点在形状之间流动，不硬切；字碎成尘、尘再聚成字；重拍上有光环、横向光线、火星。
- [ ] **字不用打字机效果、不带光标**：英文小字和角标整行淡入、轻轻滑入或字距收拢；片名落定后最多一道光扫过字形。
- [ ] **审美克制**：只有关键物发光（每支片定一种“关键色”）；**字不发光、不抖**；不用抖屏、故障、闪烁乱跳。
- [ ] 大特效只给重拍，全片 3–6 次，每次前面先黑 0.45 秒。
- [ ] 缓动只用 out / inOut / in 三种；镜头每段只有一个慢推或平移。
- [ ] 人物比例要像真人（成年人有肩、腰、腿），不能是“圆头 + 一团”。
- [ ] 配乐：每支片用指定的那一首，**整首**不剪、不换曲，片长 = 歌长（无助：`wuzhu/bgm_song.m4a` 163.99 秒；懂事 v2：`dongshi/bgm_jjc.m4a` 经济舱钢琴版 104.25 秒；懂事 v3：`dongshi/bgm_v3.m4a` = 经济舱钢琴版整首放两遍，每遍都不剪，208.5 秒）；大特效卡在小节线上，字幕和动作卡在拍点附近（先测 BPM，按拍点公式反算时间）。
- [ ] 一句字幕最多对应一次画面变化；关键词颜色 = 画面里对应元素的颜色，同时出现。

## D. 字号与可读性（“字幕别太小”）

- [ ] 字幕：横屏 **≥ 52px**，竖屏 **≥ 60px**；金句 ≥ 60px；竖屏每行 ≤ 14 个字，离底边约 420–440px（避开平台标题区）。
- [ ] 角标、类型标签、画面里的小字（英文读数、引文、标签）**≥ 20px**，中文小字 ≥ 24px；手机竖屏上也要看得清关键词。
- [ ] 字幕在最上层，不被画面元素、清单、大字盖住；同一时刻不出现两行字幕叠在一起。
- [ ] 画面里的字（数字、标签、气泡）不压在人物的手、脸上，不压字幕。

## E. 我犯过的错（每次都要专门查）

### 无助（wuzhu）
- v5：结尾连说三遍“不要绝望”，和最后一句重复，还把落点拉回口号。→ 结尾只说一次。
- v5：开头把“拖延”直接等同于“习得性无助”，说得太满。→ 改成“也许不是懒”。
- v5：把“别人夸”说成完全没用，和 Bandura 的原意不符。→ 改成“涨不了多少”。
- v6：开头的求职者在结尾没再出现。→ 结尾回到开头那一幕。
- v7：什么都在发光（39 处光晕）、人物粗糙、字发光又抖、画面碎。→ 只给关键物发光，人物重画，字不发光不抖。
- 字幕被后画的元素盖住过。→ 字幕永远最后画。

### 懂事（dongshi）v1 第一次关键帧自查

### 懂事（dongshi）v1.1 开头

### 懂事（dongshi）v2（换成经济舱整首，164 → 104.25 秒）
- 片名前的光尘星云第一次几乎看不见。→ 基础亮度提高约一倍半、星云收紧、每三颗给一颗泛光；静帧里要一眼看得出“一团光在飘”。

### 懂事（dongshi）v3（内容加厚，经济舱整首放两遍，208.5 秒）

- 文案“画面”列写了“演久了，面具发灰”，第一次没做。→ 交付前把文案的“画面”列逐条对一遍静帧。

## F. 每一轮交付前的自检流程

1. **报错**：横竖两版逐帧脚本跑完，没有 `PAGE ERROR` / `CONSOLE` 报错（输出目录先清空，时间用逗号分隔，数一下帧数对不对）。
2. **关键帧**：横竖两版各抽 ≥ 50 帧（每句字幕至少一帧，每个大特效前、中、后各一帧），拼成联系表逐张看。
3. **逐张查**：
   - 出画：人物、云、伞、字有没有被画面边缘切掉；
   - 重叠：字和字、字和手 / 脸、标签和道具有没有压在一起；
   - 可读：字幕、角标、标签在手机上看不看得清（按 D 节字号）；
   - 发光：除关键色以外的东西有没有在发光；字有没有发光、抖动；
   - 特效：该华丽的地方（形状流动、聚散、重拍）有没有做到，平时画面是不是安静；关键特效（如雨倒流、聚散）在静帧里要看得出来，看不出来就加强。
   - 竖屏：左上角标（约 y 110–220）、底部字幕（约 y 1400–1560）这两块区域里不能有画面内容。
4. **文案**：按 B 节数行数、字数、留白、对仗；每句事实对照来源。
5. **结构**：结尾是否回到开头；大特效次数和前置黑场。
6. **交付**：不渲染成片、不提 token；提交只含相关文件；推送后核对分支。
7. 发现问题 → 先改 → 重新跑 1–5 → 再交付。新发现的错补进 E 节。
